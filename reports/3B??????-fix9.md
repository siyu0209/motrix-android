# 3B 全环境自适应 + 活动卡修复 · fix9

日期：2026-11-18　产物：`dist/motrix-android-2.4.3-fix9-debug.apk`
SHA-256：`10AFFBCEEFA568AF3616A7835AF5575DEB9103067836793A49D1BE3ED13C1C16`

## 目标
把"按某台设备调死"的 3B 界面改成**真正按屏幕宽度自适应**（手机 / 横屏 / 平板 / 折叠屏 / 不同分辨率与 DPI），并修复发现的问题。

## 改动
1) **流式字号与间距**（`mobile-adapt.css §18`）
   - `--mtx-font-base: clamp(13px, 0.95vw + 10.5px, 16px)`；间距 `clamp(8px,1.1vw+4px,18px)`。小屏不挤、大屏不空。
2) **设置分类自适应列数**
   - 默认 `repeat(auto-fill, minmax(205px,1fr))`：窄屏 2 列、手机横屏 3~4 列；
   - `@media(min-width:1100px)` 封顶 4 列 → 8 个分类恒定 4×2，整齐不参差。
3) **宽屏内容限宽居中**：`≥1180px` 主内容 `max-width:1440px`，避免被拉得又宽又空。
4) **弹窗限宽**：`≥600px` 弹窗 `max-width:min(92vw,780px)`、圆角 16；窄屏仍走全屏弹窗。
5) **宽表格窄屏横滚**：`≤600px` `table{display:block;overflow-x:auto}`，不撑破布局。
6) **极矮横屏 / 大平板竖屏** 专项微调字号间距。
7) **修复「活动」卡报错**：新增 `query:getTaskActivity` 返回合法 `TaskActivitySnapshot`（0 值日历），不再出现"无法获取活动数据"。

## 多宽度实测（模拟视口宽度）
| 宽度 | 仪表板 | 设置页 |
|---|---|---|
| 360 | 单列/卡片存在（DOM 证实），无横向溢出 | 2 列，8 分类可见 |
| 640 | 多列，无溢出 | 3~4 列 |
| 800 | 多列整齐，活跃任务无报错 | 4 列 |
| 1280 | 多列铺满，「活动」日历正常渲染 | **4×2 全部可见、无裁切** |

## 说明 / 局限
- 我用的 `?vw=W` 只固定 CSS 宽度，设备物理高度不变，所以窄宽度截图会"整体放大只看到顶部"——这是**测试工具假象，不是界面 bug**（DOM 探针确认 360 下引擎/活跃任务/传输等卡片均在）。
- 真机（另一部手机 / 平板）的最终手感，需要你把那台设备连上后我实机逐台校验；不同 DPI 的清晰度、折叠屏展开态届时一并看。

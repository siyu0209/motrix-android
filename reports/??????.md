## 4. 移植架构（两条真实路线）
Motrix 上游 = **React Web UI ↔ HTTP JSON-RPC + WebSocket ↔ Fastify 后端 + core（aria2/ffmpeg 子进程）** 的 client-server 结构（原生自带 web/server 目标与远程部署）。据此：

| 模式 | 实现 | 原生依赖 | 状态 |
|---|---|---|---|
| **A. remote（已交付 APK）** | WebView 加载 Motrix 官方 Web UI（或其托管 UI），连远程 Motrix server | 零原生依赖 | ✅ **已实编出 APK** |
| **B. embedded（工程已搭，未实编）** | nodejs-mobile 跑 `dist/server` + aria2c 安卓二进制，WebView 连 127.0.0.1 | better-sqlite3/aria2c/nodejs-mobile 交叉编译 | ⏳ 骨架就绪，原生模块待攻 |

移动适配：`renderer-overrides/mobile-adapt.css|js`（安全区、44px 触控、窄屏单列、弹窗全屏、输入 16px 防缩放、底栏避让、暗色、返回键接管），构建时打入 `assets/`，页面 `onPageFinished` 自动注入。

## 7. 使用方式（模式A，推荐）
1. 起一个 Motrix server（二选一）：
   - Docker：在官方仓库 `docker compose up`
   - 源码：`pnpm install && pnpm build:server && MOTRIX_SKIP_ELECTRON_REBUILD=1 node dist/server/index.mjs`
2. 手机与服务器同网；安装 APK 后首启，在配置面板填 `http://<服务器IP>:<端口>` → 连接。
3. 进入官方 Motrix 完整 UI（下载/任务/BT/磁力/限速/统计）。

## 8. 诚实边界（未验证/需真机复验项）
1. **端到端联调**：本机无连接设备（`adb devices` 为空）与无运行中的 Motrix server，故**未做真机安装与页面联调**；需在真机上复验 UI 适配与 RPC 连通。
2. **鉴权引导（P0 建议改进）**：服务端 `/rpc /api /rpc/events` 默认需登录，仅放行 `/healthz`、`/rpc/auth/login|status` 与静态 GET。remote 模式下官方 UI 自带登录/配对界面，用户可在 UI 内完成；若要「免交互自动登录」，应读取 `<dataDir>/operator-token` 后 POST `/rpc/auth/login` 拿 `mtx_op` cookie 再 reload（详见 docs/02、docs/07 坑 5），本版未强制注入，保留官方登录流程。
3. **模式B 三大硬骨头未实编**：① better-sqlite3 原生 C++（NDK 交叉编译）；② aria2c 安卓二进制（只认 `MOTRIX_ARIA2_BIN`）；③ nodejs-mobile 的 Node 版本 vs 目标 node22。另有 4 处引导脚本契约不一致（C1–C5：PORT/MOTRIX_ARIA2_BIN/startNodeWithArguments 不注入 env/ready 文件路径/登录注入），已在 docs/02 §5 与 docs/07 逐条列明，待执行角色修 `assets/nodejs-project/main.js` 后攻坚。
4. **aria2 二进制**：脚本从社区源拉取，sha256 需人工复核；GPLv2 需随包提供源码获取方式（NOTICE 已备）。
5. **UI 细节**：官方 UI 为桌面向布局，移动端适配为通用注入，极端 DOM 变化处需按 `renderer-overrides/screens.md` 微调。

### D-3B-02　仪表板（Dashboard）底部内容被裁切

- **用户原话**：「仪表板的界面，下面那一块像是直接被切掉一样」
- **专业需求**：进入仪表板页面后，页面**底部内容（最后一块卡片/统计区/列表底部）被整块裁掉或显示不全**，无法滚动看到完整底部。需保证仪表板整页在 K60 竖屏（含系统导航栏/安全区）下**底部内容完整可见、可滚动到底、无截断**。
- **可复现步骤**：
  1. K60 竖屏，打开 Motrix Android（remote 模式已连服务器），进入 3B 界面；
  2. 左侧点「仪表板 / Dashboard」进入仪表板页；
  3. 向下滚动到底 → 观察最底部卡片/统计区是否被切掉、是否无法再滚动看到完整内容。
- **期望 vs 现状**：
  - 期望：底部内容完整呈现，能滚动到底，末块不被裁。
  - 现状：底部像被"直接切掉"，内容不全。
- **验收标准**：
  1. 仪表板**滚动到底时，最后一块内容完整可见**（含底部内边距，不被导航栏/刘海遮挡）；
  2. 无「内容溢出但滚不动」的截断（滚动条能到达真实底部）；
  3. 冷启动到本页无横向溢出、无白屏；K60 竖屏 + 常见安全区下均成立。
- **责任 agent**：**主** multiplatform-dev（改移动适配层/壳的布局约束）；**协** reverse-auditor（定位裁切根因——疑点见下）、ui-ux（给出底部留白/安全区视觉基线）、qa（验收）。
- **优先级**：**P0**（内容被裁=信息不可达，属核心可用性破坏）。
- **根因线索（供 reverse-auditor 参考，非结论）**：`docs/10 §1.3` 载明 `SidebarInset` 带 `min-h-0 overflow-hidden`，若仪表板内部用 `100vh`/固定高度而非 `dvh`+`min-h-0` 弹性，容易被容器 `overflow-hidden` 裁掉底部；另需排查 WebView 是否吃到 `env(safe-area-inset-bottom)`（`docs/10 §7` 已提示安卓安全区需在 3B 侧叠加）。

### D-3B-03　隐藏侧栏后，下载页「下载状态分类栏」与 M·O 顶栏重叠

- **用户原话**：「一开始说的 M·O 字幕重叠：是点击侧边栏隐藏后，下载界面的【下载状态分类栏】会重叠」——即：隐藏侧边栏后，下载页顶部的状态分类/筛选栏与 M·O 顶栏重叠。
- **专业需求**：在下载页，**点击折叠（隐藏）左侧栏后**，下载页顶部的「下载状态分类/筛选栏」会与顶部 M·O 顶栏（40px 固定透明覆盖条）**发生重叠/压盖**，导致筛选栏第一行被顶栏遮住或与 m·o 徽标文字叠在一起、点击被拦截。需保证：侧栏隐藏状态下，下载页状态分类栏与 M·O 顶栏**不重叠、不被遮挡、可正常点击**。
- **可复现步骤**：
  1. K60 竖屏，进入 3B 界面 → 下载页；
  2. 点击顶栏「折叠侧栏」按钮隐藏侧栏（此时进入 compact-header 紧凑态）；
  3. 观察下载页顶部「下载状态分类栏」是否与 M·O 顶栏/徽标重叠、被压住、点不动。
- **期望 vs 现状**：
  - 期望：隐藏侧栏后，状态分类栏落在顶栏之下或横向让开，不重叠、可点击。
  - 现状：分类栏与 M·O 顶栏重叠。
- **验收标准**：
  1. 侧栏**展开态、收起态、<640 窄屏态**三种情况下，下载页状态分类栏**均不与 40px 顶栏重叠**；
  2. 分类栏全部按钮**可点击**（不被 z-30 顶栏命中区拦截）；
  3. 切换侧栏开合时布局无跳动错位；≥768/640–767/<640 三档断点下均通过。
- **责任 agent**：**主** multiplatform-dev（改适配层）；**协** reverse-auditor（已定位根因）、ui-ux（视觉规范）、qa（三档断点回归）。
- **优先级**：**P0**（遮挡筛选控件=下载页主功能入口不可用）。
- **根因与最稳修法（`docs/10` 已给结论，可直接采用）**：根因是**自绘的"下载状态分类栏"没有吃到应用外壳的两轴避让**——顶栏是 40px `fixed/z-30` 透明覆盖条，内容必须自行让出。侧栏隐藏后进入 `compact-header` 紧凑态，内建 `PanelShell` 会靠 `ps-[--window-chrome-safe-area-leading]`（=160px）横向让开、或 `<640` 时靠 `padding-block-start:44px(触屏56px)` 纵向下移；一旦该分类栏脱离 `PanelShell`/`data-slot="panel-shell-header"`，兜底全部失效→重叠。**修法**：①首选把状态分类栏纳入 `PanelShell` 头或加 `data-slot="panel-shell-header"`；②不能改 DOM 时按 `docs/10 §6.2` 显式选择器补 `padding-block-start`（竖轴）+ `padding-inline-start:var(--window-chrome-safe-area-leading)`（横轴），断点严格对齐 768/640/pointer:coarse 三档，勿自造 600/720。

### D-3B-04　隐藏侧栏后，下载页/Trackers 页很难把侧栏重新唤起

- **用户原话**：「下载页和 Trackers 页，点击隐藏侧边栏后，再想点击把侧边栏召唤出来就很难成功」
- **专业需求**：在下载页与 Trackers 页，隐藏侧栏后，用于**重新唤起侧栏的触发按钮命中区过小/被顶栏遮挡/不易点中**，用户需要反复试才能点到。需保证侧栏有**清晰可见、命中区足够大（建议 ≥44×44dp 触控热区）、不被其它元素遮挡**的唤起入口，一次点击即可召回。
- **可复现步骤**：
  1. K60 竖屏，进入 3B 界面 → 下载页（再切到 Trackers 页验证）；
  2. 点击折叠侧栏隐藏；
  3. 尝试点击顶栏「折叠/展开侧栏」触发按钮把侧栏唤出 → 观察是否点不中、需要多次尝试、或按钮被顶栏/内容盖住。
- **期望 vs 现状**：
  - 期望：唤起按钮命中区 ≥44×44dp、可见、一次点击成功召回。
  - 现状：命中区太小/难点，需反复尝试。
- **验收标准**：
  1. 下载页与 Trackers 页，侧栏隐藏状态下，**单次点击召回成功率 = 100%**（连点测试 10 次全命中）；
  2. 触发按钮**实际可点击热区 ≥44×44dp**（不足则用透明扩展区补足，不改视觉尺寸）；
  3. 触发按钮 `z` 层级高于内容且**不被 40px 顶栏或页面元素拦截**；
  4. 唤起后侧栏完整展开、无残影。
- **责任 agent**：**主** ui-ux（定义命中区/触控热区与位置规范）；**协** multiplatform-dev（实现扩大热区/提升 z-index/改按钮尺寸）、reverse-auditor（定位触发按钮 DOM 与实际命中区，参考 `docs/10 §2.3`：触发器约 28px、簇宽≈152px）、qa（连点回归）。
- **优先级**：**P1**（影响效率但有规避——系统手势/其他入口，非完全阻断）。
- **根因线索**：`docs/10 §2.3` 记录折叠侧栏触发按钮为 `size-7`（28px），低于 44dp 触控建议；且顶栏为 `fixed/z-30` 覆盖层，若按钮被内容或其它层压住会"点不动"。需 reverse-auditor 在 K60 上核对实际命中区与 z 层级后再给精确修法。

### D-3B-05　缺少「3B 界面 → 原生界面」的返回入口

- **用户原话**：「只有原生界面进入 3B 的按钮，没有 3B 进入原生的按钮」
- **专业需求**：当前只有「原生界面 → 3B 界面」的进入按钮；**缺少从 3B 界面返回原生界面的入口**。需在 3B 界面提供一个明确、稳定可达的「返回原生界面」入口（按钮/菜单项），点击后能从 WebView 业务界面回到 Android 原生壳界面，并保证来回切换不丢状态、不白屏。
- **可复现步骤**：
  1. K60 竖屏，从原生界面点「进入 3B」进入 WebView 业务界面；
  2. 在 3B 界面四处查找是否存在「返回原生界面」按钮/入口；
  3. 结果：找不到返回原生的入口（只能靠系统返回键或无法返回）。
- **期望 vs 现状**：
  - 期望：3B 界面有明确的「返回原生界面」按钮/入口，一键回到原生壳。
  - 现状：只有进、没有回。
- **验收标准**：
  1. 3B 界面存在**可见且可点击**的「返回原生界面」入口（按钮或顶栏/侧栏菜单项，位置固定、文案清晰）；
  2. 点击后**稳定回到原生界面**（一次点击成功率 100%），无白屏/无卡死；
  3. 返回后再进 3B，**登录态/下载列表/滚动位置不丢失**（状态保持）；
  4. 与系统返回键行为一致、不冲突（原生侧统一处理返回导航）。
- **责任 agent**：**主** multiplatform-dev（新增 JS 桥/入口 + 原生侧切面）；**协** ui-ux（按钮位置与样式规范）、reverse-auditor（先确认现有导航机制：`window.MotrixAndroid.onBack`/`mtx:native-back` 及 WebView 与原生壳的切换现状）、qa（来回切换回归）。
- **优先级**：**P1**（导航闭环缺失；若经确认"除系统返回键外无任何回原生路径"，则升 **P0**）。
- **备注**：现有桥已具备 `window.MotrixAndroid.onBack()` 与 `mtx:native-back` 事件（见 `docs/07 §3`、`docs/08 §9`），优先评估**复用现有桥扩展一个 `exitToNative()`/显式返回入口**，避免新造机制。

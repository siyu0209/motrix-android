## 3. 术语表（给零基础读者）

| 大白话 | 专业术语 | 一句话解释 |
|---|---|---|
| 软件外壳 | Electron | 桌面版 Motrix 的"运行容器"，安卓上**用不到**，改用 WebView + 本机服务替代 |
| 手机里的浏览器窗口 | WebView | 安卓自带的"网页显示组件"，用来显示 Motrix 的界面 |
| 界面 | renderer / renderer-web | Motrix 的网页界面（React 写的），安卓端直接复用 |
| 后台服务 | Fastify server / dist/server | 真正干活的"服务端程序"，负责和下载引擎通信、保存任务 |
| 下载引擎 | aria2(c) | Motrix 用来真正下载 HTTP/BT/磁力的开源内核，安卓端用它的安卓版二进制 |
| 在手机里跑 Node | nodejs-mobile | 让安卓 App 内部能运行 Node.js 程序的技术（模式 B 的核心） |
| 磁力链接 | magnet | 以 `magnet:?xt=urn:btih:...` 开头的下载地址 |
| BT 种子 | torrent | `.torrent` 文件，描述一个 BT 资源 |
| 下载引擎遥控协议 | RPC / JSON-RPC | 服务端用它与 aria2 通信、下达下载指令 |
| 手机存储授权框架 | SAF（Storage Access Framework） | 安卓让用户自己挑一个文件夹授权的机制，应用无需全盘存储权限 |
| 手机 CPU 架构 | ABI（arm64-v8a / armeabi-v7a） | 不同手机芯片指令集，需分别打包对应的 aria2 二进制 |
| 安卓原生开发套件 | Android SDK / NDK | 编译安卓 App 的工具；NDK 用于编译 C/C++ 原生库 |
| 交叉编译 | cross-compile | 在电脑上为目标手机芯片编译原生库（如 sqlite、Rust 模块） |

## 4. 源版本与工程判定（与 BLUEPRINT 对齐）

- **上游项目**：`agalwood/Motrix`，目标版本 **v2.4.3（motrix-turbo）**。许可与版权信息需在交付物中保留（见文档 05）。
- **技术栈**：Electron + React Web renderer + Fastify server + aria2 下载引擎（+ 视情况 ffmpeg）。
- **可移植性判定**：Motrix 本质是"网页界面 ↔ HTTP/bridge ↔ 本机服务端 + 下载引擎"的**客户端/服务端结构**，服务端可独立运行。**安卓端不需要 Electron**，只需三样：① WebView 承载界面；② 本机后端服务（模式 B）或远程服务器（模式 A）；③ 安卓版 aria2 二进制。
- **双模运行（架构默认决策，非用户明说，见 §6 默认补充 D2）**：
  - **模式 B（默认）**：App 内用 nodejs-mobile 跑真实 `dist/server` + 安卓 `aria2c`，全部在本机 `127.0.0.1:<端口>`，离线可用，最忠实。
  - **模式 A（兜底/轻量）**：手机当遥控端，连一台跑 Motrix server 的 PC/NAS（填 URL + bridge 配对）。

> 说明：具体功能清单以源码审计（`docs/01-源码审计.md`，reverse-auditor）为事实依据；本文所列核心业务来自用户明说项 + 原版通用能力，若审计发现差异，以审计为准并回写本文。

## 7. 功能保真标准（如何判定"移植成功"）

为避免"看起来像"变成"其实没做到"，定义四级保真度，每项核心功能都必须归到其中一级并留证据：

| 等级 | 名称 | 判定口径 | 典型例子 |
|---|---|---|---|
| **L1** | 完全保真 | 业务逻辑与交互与原版一致，仅做布局适配；后端接口、数据结构不变 | 任务列表状态机、aria2 RPC 调用、限速参数 |
| **L2** | 近似保真 | 行为等价，底层实现替换但对外表现一致 | Electron IPC → WebView JS 桥 + HTTP；桌面通知 → 安卓通知 |
| **L3** | 替代实现 | 桌面独占能力用安卓等价物实现，交互不同但目的达成 | 文件对话框 → SAF；拖拽 → 选择文件；托盘 → 常驻通知+应用内菜单 |
| **L4** | 不支持（须给替代） | 安卓无等价能力，明确标注并给替代路径 | 自动更新（→应用商店/手动 APK）；系统托盘 |

**验收总则**：核心业务（U3a–U3g）必须达到 **L1 或 L2**；桌面外壳类能力允许 **L3/L4**，但每一处 L3/L4 都必须在 `docs/04-差距与路线图.md` 登记"替代方案 + 需真机验证"。

## 8. 安卓手机端**硬性验收标准**（量化、可测）

> 这些是"能不能算移植成功"的硬门槛。标注 **[真机]** 的必须在真实安卓手机上测，离线文档无法代替；标注 **[构建]** 的需完整工具链（JDK17+Android SDK/NDK）才能验证。

| 编号 | 指标 | 阈值 / 通过条件 | 测量方法 | 环境 |
|---|---|---|---|---|
| **A1** | 冷启动时间 | 点图标到主界面**可交互 ≤ 3 秒**（中端机，如骁龙 6/7 系、8GB、Android 10+） | `adb shell am start -W` 看 TotalTime；或录屏逐帧 | [真机] |
| **A2** | 核心流程可用 | HTTP 下载成功、magnet 添加并下载、BT 种子下载、暂停/继续/删除、限速生效、统计刷新、设置保存——**7 项全过** | 手工用例（文档 06）+ 回归脚本 | [真机] |
| **A3** | 权限最小化 | 仅申请 INTERNET、FOREGROUND_SERVICE(+DATA_SYNC)、POST_NOTIFICATIONS；无通讯录/短信/定位/全盘存储；存储走 SAF | 安装后看系统权限页；`aapt dump permissions` 核对 | [构建]+[真机] |
| **A4** | 无强制广告 / 无后台自启 | 无广告 SDK；默认不 BOOT_COMPLETED 静默自启；退出后不驻留后台偷跑 | 静态查 manifest/依赖；真机重启观察 | [构建]+[真机] |
| **A5** | 竖屏适配 | 360dp 宽下主要页面无横向滚动、无元素溢出、关键按钮可点（≥48dp 点击区） | 竖屏逐页截图核对 | [真机] |
| **A6** | 稳定性 / 内存 | 连续 30 分钟下载不崩溃；后台内存无持续单调增长（PID RSS 不持续攀升） | 长跑 + `dumpsys meminfo` | [真机] |
| **A7** | 网络切换 | Wi-Fi ↔ 移动网络切换时任务可继续或给出明确失败提示，不静默卡死 | 手动切网 | [真机] |
| **A8** | 存储可见 | 下载文件落在用户选定目录（SAF），系统文件管理器可看到、可打开 | 下载后到文件管理器查看 | [真机] |
| **A9** | 后台保活 | 前台服务通知常驻且显示进度；锁屏/切后台下载不中断 | 锁屏 10 分钟观察 | [真机] |
| **A10** | 安全基线 | WebView 关闭 file 越权访问、JS 桥只暴露白名单方法、无明文存储敏感信息、远端 HTTPS 校验保留 | 代码审查 + 静态扫描 | [构建] |

**关于 A1≤3s 的诚实说明**：3 秒阈值受机型、首次安装冷启动、nodejs-mobile 初始化耗时影响，**必须真机实测**；如模式 B 因内嵌 Node 启动偏慢，需评估"模式 A 秒开 / 模式 B 首次稍慢"的分档口径并回写本文。（风险详见文档 04 §5 R3。）

## 9. 需求边界与"不做项"（防止范围蔓延）

**明确不做**（用户未要求，且会显著扩大成本；如需再做请用户显式提出）：

1. 不做 iOS 端。
2. 不重写 aria2 下载引擎（复用官方/安卓版二进制）。
3. 不复刻桌面独有外壳：**系统托盘、自动更新器、多窗口/偏好设置独立窗口、原生菜单栏/全局快捷键**（改为替代方案，见文档 04）。
4. 不做平板/横屏的专项精修（竖屏优先；横屏能显示、可用，不保证逐页完美）。
5. 不做账号体系 / 云端同步 / 会员（原版本就没有）。
6. 不破解、不绕过任何第三方付费或版权限制；仅做开源下载器的移植。
7. 不保证第三方 tracker / DHT 节点 / 特定资源的可达性（取决于网络与资源本身）。

**边界内但依赖外部条件**（能做，但结论受环境限制，需诚实标注）：

- BT/磁力实际连通性取决于公网 tracker/DHT 与运营商网络；
- 后台保活在国产 ROM（MIUI/EMUI/ColorOS 等）可能被系统省电策略杀，需引导白名单；
- 原生模块（better-sqlite3 / Rust native-host）能否端内跑通取决于交叉编译（见文档 04 §5）。

## 10. 优先级与分期（详见文档 04）

本文只给结论性分期，路线图与每期验收口径在 `docs/04-差距与路线图.md`：

- **P0（MVP 核心闭环，必须）**：能装能启动 → 新建 HTTP 下载并完成 → 任务列表/暂停/继续/删除 → 设置持久化；模式 A 全流程 + 模式 B 内嵌最小验证。
- **P1（核心业务全量保真）**：BT、磁力、限速、统计、设置全量、SAF 目录、前台保活、通知、任务恢复。
- **P2（优化与打磨）**：启动≤3s、性能内存、安全加固、UI 美化、bug 清零、magnet/.torrent 协议注册、深色模式、多语言。

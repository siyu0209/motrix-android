## 1. 这份文档解决什么问题

Motrix 是**桌面（Electron）软件**，很多能力（系统托盘、自动更新、多窗口……）在安卓上**没有一一对应的东西**。这份文档做三件事：

1. **如实列出差距**：哪些桌面能力在安卓端"做不到原样"，我们怎么替代——不夸大、不隐瞒。
2. **讲清双模覆盖**：本工程"端内内嵌（模式 B）"和"远程遥控（模式 A）"各自能覆盖什么、覆盖不了什么。
3. **给分期路线**：先做哪步、后做哪步、每步怎么算"做完"（验收口径），以及最大技术风险（原生模块编译）怎么兜底。

## 2. Electron 桌面能力 → 安卓等价性总表

> 等价性四级：**完全**（原样可做）/ **近似**（行为等价，实现替换）/ **替代**（换安卓等价能力，交互不同）/ **不可**（无等价，须给替代路径）。所有"近似/替代/不可"项都要在验收时对照。

| # | 桌面能力（Electron） | 桌面上的表现 | 安卓等价性 | 本工程处理方式 | 备注 / 需验证 |
|---|---|---|---|---|---|
| G1 | 系统托盘 Tray | 最小化到托盘、右键菜单 | **不可** | 用「前台服务常驻通知 + 应用内菜单」替代；无托盘概念 | — |
| G2 | 系统通知 Notification | 下载完成/出错弹系统通知 | **近似** | 安卓系统通知（需 POST_NOTIFICATIONS 权限） | 真机验证通知渠道 |
| G3 | 自动更新 electron-updater | 自动下载安装新版本 | **不可** | 关于页放"检查更新"链接；发布新 APK 由用户/商店安装 | 不上架商店则靠手动更新 |
| G4 | 多窗口（主窗 + 偏好设置窗） | 独立弹出设置窗口 | **替代** | 单 WebView，设置用 SPA 内路由/弹层实现 | 交互与原版不同，功能一致 |
| G5 | 原生菜单栏 / 全局快捷键 | File/Edit 菜单、快捷键 | **替代** | 改为界面内按钮/图标操作 | — |
| G6 | 单实例锁 | 防重复启动 | **近似** | 单 Activity 天然单实例 | — |
| G7 | 协议注册 `magnet://` / 文件关联 `.torrent` | 点磁力/种子自动唤起 | **近似** | Android Intent Filter（magnet / `application/x-bittorrent` / `content://`） | 需真机验证唤起链路 |
| G8 | 拖拽文件到窗口 | 拖拽添加种子 | **不可** | 用 SAF「选择文件」添加 | — |
| G9 | 原生文件选择对话框 | 选下载目录/种子 | **替代** | SAF（Storage Access Framework）选择目录/文件 | 见 G13、R8 |
| G10 | 「在文件夹中显示」/ 打开文件 | 打开下载目录 | **替代** | FileProvider + 系统文件管理器 Intent | — |
| G11 | 剪贴板监听（自动识别链接/磁力） | 后台监听剪贴板 | **替代/受限** | Android 10+ 后台读剪贴板受限；仅前台时读取或手动粘贴 | 真机/系统版本差异 |
| G12 | 渲染层⇄主进程 IPC | ipcRenderer/ipcMain | **替代** | WebView `addJavascriptInterface` JS 桥 + 本机 HTTP server | 桥最小暴露（安全 A10） |
| G13 | 系统代理设置 | 跟随/自定义代理 | **近似/受限** | 应用内 aria2 代理设置为主；系统级代理安卓管控严 | 需验证 aria2 代理生效 |
| G14 | 抑制系统休眠 powerSaveBlocker | 下载时阻止睡眠 | **替代** | 前台服务 + WakeLock（部分 ROM 仍需用户白名单） | 见 R7 |
| G15 | 硬件加速 / 大窗口 | GPU 渲染 | **近似** | WebView（硬件加速默认开） | 大列表性能见 R6 |
| G16 | 跟随系统主题（深/浅色） | 自动切换主题 | **近似** | WebView `prefers-color-scheme` 跟随安卓深色模式 | 需验证样式联动 |
| G17 | 系统级开机自启 | 开机自动运行 | **不默认做** | 默认不注册 BOOT_COMPLETED；仅用户可选开启（D6） | — |
| G18 | 多语言切换 | 语言菜单 | **近似** | 复用原版 i18n；语言选择在设置内 | — |

**结论**：核心下载/任务/限速/统计/设置业务（L1/L2 保真）**不受上表影响**——它们本来就是"界面↔HTTP↔服务端"，安卓照搬即可。受影响的只是**桌面外壳类**能力，且均已给出替代（L3）或标注不可（L4）。全部 L3/L4 项在验收时逐条对照本表打勾。

## 3. 双模能力覆盖矩阵

> 模式 B＝端内全内嵌（nodejs-mobile 跑 `dist/server` + 安卓 `aria2c`，离线可用，最忠实）；模式 A＝手机连外部 Motrix server（遥控端）。

| 能力 | 模式 B（端内内嵌） | 模式 A（远程遥控） | 说明 / 依赖 |
|---|---|---|---|
| renderer 界面复用 | ✅ 完全 | ✅ 完全 | 两者共用同一 WebView + renderer 资源 |
| HTTP/HTTPS/FTP 下载 | ✅（依赖 aria2c 可执行） | ✅（依赖远端 server） | B 需 aria2 安卓二进制就绪 |
| BT / 磁力 | ✅（依赖 aria2c + DHT/tracker） | ✅ | 连通性受网络/资源影响 |
| 任务管理/暂停/继续/删除 | ✅ | ✅ | 逻辑在 server 侧，两者一致 |
| 限速 / 统计 / 设置 | ✅ | ✅ | 设置持久化依赖 sqlite（见 R1） |
| 任务/设置持久化 | ⚠️ 依赖 sqlite 方案 | ✅ 远端负责 | B 端受 better-sqlite3 交叉编译影响 |
| 离线可用 | ✅ 是 | ❌ 否（需连服务器） | A 的本质是遥控 |
| 下载目录（SAF） | ⚠️ 需把 SAF 目录映射给 aria2 | ✅ 远端目录 | 见 R8 |
| 前台保活/通知 | ⚠️ 需前台服务+WakeLock | ⚠️ 仅保 WebView 连接 | 见 R7 |
| Rust native-host 相关能力 | ❌ 预置不打包 | ⚠️ 由远端决定 | 见 R2，需审计确认是否核心 |
| 部署门槛 | 高（要完整工具链把 Node+aria2 打进 App） | 低（有台 PC/NAS 即可） | A 也是 B 出问题时的兜底 |

**战略结论**：**模式 A 是"快速可用 + 兜底"基线**（不依赖原生模块，最快验证 renderer 与后端契约）；**模式 B 是"最忠实"目标**（离线、单机全内嵌），但受 R1/R2/R3 原生模块与 Node 版本制约，需单独攻坚。两模共用同一 WebView 壳，差异只在"后端指向 localhost 还是远程 URL"——因此**先做壳 + 模式 A 打通，再攻模式 B 内嵌**是风险最低的推进顺序。

## 4. P0 / P1 / P2 分期路线图

> 每期都必须"可演示、可验收"，未过验收不进入下一期。责任角色见 `docs/05-交付清单.md`。

### P0 · 核心闭环 MVP（必须先达成）

- **目标**：证明"能装、能启动、能下一个文件、能管理任务"。
- **范围**：
  1. Android 壳：Gradle 工程 + WebView 承载本地 renderer；JS 桥骨架（getServerBase / pickDownloadDir / notify / storageInfo / keepAwake）。
  2. **模式 A 打通**：WebView 连远程 Motrix server，完成 HTTP 新建→下载→暂停/继续/删除全流程。
  3. **模式 B 最小验证**：nodejs-mobile 能加载 `assets/nodejs-project/main.js`、起 Fastify（健康检查通过）、能拉起安卓 `aria2c` 并完成**单个 HTTP 任务**。
  4. 设置持久化按最简方案（如远端或纯 JS 兜底先跑通）。
- **交付**：可安装 debug APK + 对应源码/脚本 + 本阶段报告。
- **验收口径**：模式 A 核心 7 项流程（文档 00 §8 A2）通过；模式 B 至少"HTTP 单任务下载成功"；壳无白屏；竖屏基本可点。**[真机]**
- **依赖**：renderer 构建成功（build-renderer）、aria2 二进制就位、nodejs-mobile 集成。
- **主要风险**：R3（Node 版本）、R4（aria2 二进制）、R9（端口）。

### P1 · 核心业务全量保真

- **目标**：把用户明说的核心业务全部做到 L1/L2 保真。
- **范围**：BT、磁力完整流程；限速（全局）；统计；设置全集与持久化（sqlite 方案定型）；SAF 下载目录落地；前台服务保活 + 通知进度；任务恢复（重启后任务不丢）；A7 网络切换处理。
- **关键攻坚**：**better-sqlite3 端内方案**（交叉编译成功 O R 纯 JS 兜底，见 R1）；ffmpeg 视审计取舍（R5）。
- **验收口径**：文档 00 §8 **A2 全 7 项通过 + A3 权限 + A8 存储可见 + A9 后台保活**。**[真机]**
- **依赖**：P0 完成；sqlite 方案定案。
- **主要风险**：R1、R2、R6、R7、R8。

### P2 · 优化与打磨

- **目标**：达到"好用、稳、安全、好看"。
- **范围**：冷启动 ≤3s（A1）；长列表性能/内存（A6）；WebView 安全加固与 JS 桥最小化（A10）；UI 美化（`renderer-overrides`）；bug 清单 P0/P1 清零（A2 回归）；`magnet://` 与 `.torrent` 协议注册（G7）；深色模式（G16）；多语言。
- **验收口径**：文档 00 §8 **A1–A10 全绿（真机 + 构建）**；缺陷清单 P0/P1=0。
- **依赖**：P1 完成。
- **主要风险**：R7（国产 ROM 杀后台）、性能硬指标。

### 分期一览

| 期 | 一句话 | 核心业务覆盖 | 硬验收 | 前置 |
|---|---|---|---|---|
| P0 | 能装能启动能下一个 | HTTP + 基础任务管理（模式A全 / 模式B HTTP 单任务） | A2 部分、竖屏基本 | — |
| P1 | 核心业务全量保真 | + BT/磁力/限速/统计/设置全量/持久化/保活 | A2 全、A3、A8、A9 | P0 |
| P2 | 好用稳安全好看 | 全量 + 优化 + 美化 + 协议 + 明暗主题 | A1–A10 全绿 | P1 |

## 5. 关键技术风险与备选方案（诚实标注）

> 风险等级：🔴高 / 🟠中 / 🟢低。**"最终结论"一栏凡标 [真机]/[构建] 的，离线文档无法给出定论，必须实机/完整工具链验证。**

| # | 风险 | 等级 | 影响 | 备选 / 处理方案 | 最终结论需 |
|---|---|---|---|---|---|
| **R1** | `better-sqlite3`（C++ 原生模块）需针对 Android NDK 交叉编译 | 🔴高 | 设置/任务持久化走不通 → 影响 U3d/U3g | ①尝试 NDK 交叉编译 `node-gyp`；②**纯 JS 兜底**（改用 `sql.js`/`@journeyapps/sqlcipher` 纯 JS 或 JSON 文件持久化）；③模式 A 由远端负责持久化 | [构建] 验证编译；兜底方案 [真机] |
| **R2** | `.cargo` / `packages/native-host`（Rust 原生模块） | 🟠中 | 若承载核心能力则端内不可用 | 先由**源码审计确认是否为桌面专属**（浏览器扩展/系统集成类多半非核心）；非核心则模式 B 不打包，模式 A 覆盖 | [构建] + 审计结论 |
| **R3** | nodejs-mobile 内置 Node 版本可能低于 26，server 用到的新 API 缺失 | 🔴高 | 模式 B 后端起不来或崩溃 | ①核对 `dist/server` 依赖的 Node API；②降级/加 polyfill/垫片；③若不可行则模式 B 降级为"模式 A 为主" | [构建] + 版本核对 |
| **R4** | 安卓版 `aria2c` 二进制来源 & 可执行位（`jniLibs/<abi>/libaria2c.so`） | 🟠中 | 下载引擎跑不起来 → 核心业务全废 | 采用社区预编译或自编译 arm64-v8a/armeabi-v7a；启动赋 0755 权限、经 `MOTRIX_ARIA2_PATH` 指定；保留 LICENSE/来源 | [真机] |
| **R5** | ffmpeg（若 server 依赖） | 🟢低 | 包体增大或个别功能缺失 | 审计确认是否必需；非必需不打包；必需再找安卓版或替代 | [构建] |
| **R6** | WebView 大列表性能/内存 | 🟠中 | 任务多时卡顿/内存涨（A6） | 列表虚拟化、分页、减少重绘；必要时 renderer-overrides 做移动端精简 | [真机] |
| **R7** | 后台保活被国产 ROM 省电策略杀 | 🟠中 | 锁屏下载中断（A9） | 前台服务 + WakeLock + 引导用户加白名单/关省电限制 | [真机]（多厂商） |
| **R8** | SAF 目录 URI 与 aria2 路径映射 | 🟠中 | aria2 无法直接写入 SAF URI | 采用"中转目录 + 完成后搬移"，或用 `MANAGE_EXTERNAL_STORAGE` 申请（谨慎，影响 A3 权限最小化） | [真机] |
| **R9** | 本机端口冲突 / localhost 绑定 | 🟢低 | 服务起不来 | 动态端口探测绑定 `127.0.0.1:0`；失败重试 | [真机] |
| **R10** | 包体膨胀（Node 运行时 + aria2 + renderer + 原生库） | 🟢低/🟠中 | 下载安装体积大 | 按 ABI 分包（split APK）、资源压缩、去除无用语言包 | [构建] |

**风险总述（给非技术读者）**：最大不确定是 **R1（sqlite 原生库）** 和 **R3（手机内 Node 版本）**——它们决定"端内全内嵌（模式 B）"能不能跑通。因此工程采取"**模式 A 先保证能用，模式 B 尽力攻坚，跑不通就以模式 A 兜底**"的策略，确保任何情况下都有可用交付。

## 6. 必须真机 / 工具链才能最终验证的点（诚实清单）

以下结论**离线写文档无法产出，只能在真机或完整构建后确认**，交付时须如实标注"待验证/已验证"：

1. **A1 冷启动 ≤3s** —— 受机型与 nodejs-mobile 初始化影响，需真机 `am start -W`。
2. **R1 sqlite 交叉编译能否成功** —— 需 JDK17 + Android SDK/NDK 工具链。
3. **R3 nodejs-mobile Node 版本能否满足 server** —— 需构建后运行核对。
4. **R4 aria2c 在具体 ABI 上是否可执行** —— 需真机（arm64/armv7）。
5. **BT/磁力实际连通性** —— 需公网 tracker/DHT + 真实资源。
6. **A9 后台保活在具体厂商 ROM 上的存活率** —— 需多品牌真机。
7. **G7 magnet/.torrent 系统唤起链路** —— 需真机安装验证 Intent。
8. **R8 SAF 与 aria2 写入可行性** —— 需真机验证目录映射。

> 红线条呼应（BLUEPRINT §5）：以上凡"未验证"的，交付文档一律标"⚠️待真机/工具链验证"，不得写成"已实现/已验证"。这是诚实交付的硬要求。

## 7. 关键路径与推进顺序（建议）

```
renderer 构建成功 ─┐
aria2 安卓二进制 ─┼─▶ 模式A打通(P0) ─▶ 壳+桥完善 ─▶ 模式B最小验证(P0) ─┐
nodejs-mobile 集成 ┘                                                    │
        ┌───────────────────────────────────────────────────────────┘
        ▼
   sqlite方案定案 & Node版本核对(R1/R3) ─▶ 核心业务全量(P1) ─▶ 优化/美化/安全(P2) ─▶ 真机全量验收
```

**并行建议**：模式 A 打通与模式 B 的 R1/R3 攻坚可并行（不同角色）；UI 美化与构建脚本可较早并行启动以缩短总工期。

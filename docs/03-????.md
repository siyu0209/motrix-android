# Motrix 安卓移植 · 构建指南（docs/03）

> 面向**零基础**用户的完整构建说明。读完照做即可从源码打出 `app-debug.apk`。
> 权威架构与目录口径见上层 [`../BLUEPRINT.md`](../BLUEPRINT.md)；本文只讲「怎么把它跑起来」。

---

## 0. 一句话总览

用 `scripts/build-all.ps1` 一条命令干完：装工具链 → 构建前端/后端 → 取安卓版 aria2 → 摆进安卓工程 → `gradlew assembleDebug` 出 APK。
它内部串了 4 个脚本，你也可以分步单独跑（见第 3 节）。

```
motrix-android/
├─ scripts/
│   ├─ install-toolchain.ps1     # JDK17 + Android SDK/NDK（幂等，已装则跳过）
│   ├─ build-renderer.ps1        # pnpm 构建 dist/renderer-web + dist/server 并 stage 进 assets
│   ├─ fetch-aria2-android.ps1   # 取 android aria2c（arm64-v8a / armeabi-v7a）
│   └─ build-all.ps1             # 一键：上面三个 + staging + gradlew assembleDebug
├─ docs/03-构建指南.md            # 本文件
└─ third_party/aria2/            # aria2c 落地 + NOTICE.md + manifest.json
```

## 1. 环境要求

| 组件 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 10/11 x64** | 脚本为 PowerShell；Win10+ 自带 `tar.exe`（解 `.deb` 用） |
| 磁盘 | **≥ 15 GB 空闲** | Android SDK + NDK(r26) 约 3~4 GB，pnpm 依赖 + Gradle 缓存若干 GB |
| 网络 | 能访问 npmjs / dl.google.com / api.adoptium.net / github.com | 首次构建需下载 |
| Node.js | **≥ 18（建议 20 LTS 或 22 LTS）** | `build:server` 用；本机当前为 v26.3.0，可用 |
| pnpm | **≥ 8** | 脚本会自动用 corepack 启用；没有则 `npm i -g pnpm` |
| JDK | **17（必须）** | Gradle/AGP 8.x 需要 JDK17；**JDK 8 / 21 不行** |
| Android SDK | platform-tools、build-tools;34.0.0、platforms;android-34 | 由 `install-toolchain.ps1` 装 |
| NDK | 26.x（默认 26.3.11579264 = r26d） | 交叉编译原生模块用 |

> **诚实提示**：`install-toolchain.ps1` 会**真的联网下载** JDK17 / SDK / NDK（体积大）。本仓库交付时**并未替你预先下载**这些 SDK，若你机器上没有，请先跑 `install-toolchain.ps1`（见 §3.1），否则 `gradlew` 一定报「SDK location not found / No toolchains found」。

## 2. 快速开始（推荐）

打开 **PowerShell**（建议管理员，便于写系统目录与静默安装），执行：

```powershell
cd C:\工作日志\projects\motrix-android
pwsh -ExecutionPolicy Bypass -File .\scripts\build-all.ps1
```

产物：`android\app\build\outputs\apk\debug\app-debug.apk`
日志：`reports\build-all-<时间戳>.log`

若你已装好工具链、只想快速重打，跳过第 1 步：

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\build-all.ps1 -SkipToolchain
```

先把源码仓库就绪（默认 `C:\工作日志\projects\Motrix`，含 `package.json`）。若源码在别处：

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\build-all.ps1 -RepoRoot D:\src\Motrix
```

## 3. 分步构建

### 3.1 装工具链（只需一次）

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\install-toolchain.ps1
```

做的事（**幂等**，已装则跳过）：
1. 检测并安装 **JDK17（Temurin）**（Adoptium 官方 MSI 静默安装）。
2. 下载 **Android commandline-tools**，解到 `%ANDROID_HOME%\cmdline-tools\latest`。
3. 用 `sdkmanager` 接受许可并安装：`platform-tools`、`build-tools;34.0.0`、`platforms;android-34`、`ndk;26.3.11579264`。
4. 把 `ANDROID_HOME`、`ANDROID_SDK_ROOT`、`JAVA_HOME` 写进**用户级环境变量**，并把 `platform-tools`、`cmdline-tools\latest\bin`、`%JAVA_HOME%\bin` 追加进用户 `PATH`。

自定义位置/版本：

```powershell
pwsh -File .\scripts\install-toolchain.ps1 -SdkRoot D:\Android\Sdk -NdkVersion 26.1.10909125
```

> 装完**新开一个终端**让环境变量生效（脚本会同步当前会话，但其他已开窗口不会自动刷新）。
> 验证：`java -version` 应为 `17.x`；`adb version` 能输出；`echo $env:ANDROID_HOME` 有值。

### 3.2 构建前端 + 后端并 stage

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\build-renderer.ps1 -RepoRoot C:\工作日志\projects\Motrix
```

做的事：
1. 在仓库根 `pnpm install`（首次较慢；`-SkipInstall` 可跳过）。
2. `pnpm build:server`（产出 `dist/renderer-web` 与 `dist/server`；若仓库无该脚本则回落 `pnpm build`）。
3. 把 `dist/renderer-web` → `android\app\src\main\assets\renderer-web\`；
   `dist/server` → `android\app\src\main\assets\nodejs-project\dist-server\`。
   只替换这两个子目录，不动 `nodejs-project` 里的其他文件（如 `main.js`）。

### 3.3 取安卓 aria2c

```powershell
pwsh -ExecutionPolicy Bypass -File .\scripts\fetch-aria2-android.ps1
```

做的事：为 `arm64-v8a`、`armeabi-v7a` 各取一个 `aria2c`，落到
`third_party\aria2\<abi>\aria2c`，并把来源/哈希写入 `manifest.json`、许可证写入 `NOTICE.md`（GPLv2）。

- 来源优先 **Termux 官方仓库 deb**（`aarch64`=arm64-v8a，`arm`=armeabi-v7a）。
- **aria2 官方不发布 Android 二进制**（只有源码/Windows），社区二进制的 sha256 无法自动比对，`manifest.json` 中会标 `verified=false`，需人工复核。
- 离线/已手动下载时，用本地件落地（不联网）：

```powershell
pwsh -File .\scripts\fetch-aria2-android.ps1 -LocalArm64 .\aria2c-arm64 -LocalArmv7 .\aria2c-arm
```

### 3.4 打包 APK

若用 `build-all.ps1` 已包含最后两步（staging + gradle）。手动分步时：

```powershell
cd .\android
.\gradlew.bat assembleDebug --no-daemon
```

> staging 说明：`build-all.ps1` 会把 `third_party\aria2\<abi>\aria2c` 复制成
> `android\app\src\main\jniLibs\<abi>\libaria2c.so`（改名成 `lib*.so` 才会随 APK 解压到 `nativeLibraryDir`）。
> App 运行期需 `chmod +x` 并设置 `MOTRIX_ARIA2_PATH`（这部分由安卓侧代码负责，见 BLUEPRINT §四）。

## 4. 常见报错排查

### 4.1 `java -version` 显示 1.8 / 21，Gradle 报 “Unsupported class file major version” 或 “Android Gradle plugin requires Java 17”
**原因**：PATH/JAVA_HOME 指向了非 17 的 JDK（本机即存在 Oracle JDK8 与某 jdk21）。
**解决**：跑 `install-toolchain.ps1` 装 JDK17；或手动把 `JAVA_HOME` 指向 `C:\Program Files\Eclipse Adoptium\jdk-17...`，并确保 `%JAVA_HOME%\bin\java.exe` 排在 PATH 最前。`project\gradle.properties` 里可设 `org.gradle.java.home=<jdk17路径>` 强制 Gradle 用 17。

### 4.2 `SDK location not found` / `ANDROID_HOME is not set`
**解决**：跑 `install-toolchain.ps1`，或在 `android\local.properties` 写 `sdk.dir=C\:\\Android\\Sdk`（注意转义）。确认 `echo $env:ANDROID_HOME` 有值且对应目录存在。

### 4.3 `sdkmanager` 报 “licenses not accepted” / 安装中途卡在 y/n
**原因**：许可未全接受。
**解决**：手动执行 `& "$env:ANDROID_HOME\cmdline-tools\latest\bin\sdkmanager.bat" --licenses`，一路 `y`；或重跑 `install-toolchain.ps1`（它会自动喂 `y`）。

### 4.4 `better-sqlite3` 编译失败（node-gyp / MSVC / python 报错）
**原因**：`better-sqlite3` 是 C++ 原生模块，需要本地编译。
- **PC 上（跑 pnpm 构建）**：需要 Python 3 + Visual Studio Build Tools（含 C++ 桌面开发）+ node-gyp。装 VS Build Tools 后重装依赖：`pnpm rebuild better-sqlite3`。
- **Android 端（nodejs-mobile 内）**：必须用 **NDK 交叉编译**出对应 ABI 的 `.node`，且 node 头文件/ABI 必须匹配 nodejs-mobile 内置的 Node 版本（**不是**你 PC 上的 Node 26）。
- **降级方案（推荐先跑通）**：
  1. server 侧把 sqlite 走**纯 JS 兜底**（如 `sql.js` / 内存库）或干脆禁用依赖 sqlite 的持久化特性；
  2. 或先走**模式 A（远程服务器）**：手机只当 WebView 客户端，后端跑在 PC/NAS，完全绕开端内原生模块。

> 诚实标注：本机当前**未验证** better-sqlite3 的 Android 交叉编译链路（缺 SDK/NDK 且仓库未就绪）。这是本移植的**头号硬骨头**，需在真机 + NDK 环境单独攻坚，详见 `docs/04-差距与路线图.md`。

### 4.5 Rust 原生模块（`.cargo` / `packages/native-host`）交叉编译失败
**原因**：Rust 目标需 Android 目标三元组 + NDK 链接器。
**解决**：
```powershell
rustup target add aarch64-linux-android armv7-linux-androideabi
cargo install cargo-ndk
$env:ANDROID_NDK_HOME = "$env:ANDROID_HOME\ndk\26.3.11579264"
# 例：cargo ndk -t arm64-v8a -t armeabi-v7a -o .\jniLibs build --release
```
**降级**：若 native-host 仅用于可选能力，构建时关闭对应 feature / 不打该模块，先用纯 Web + server 模式跑通。

### 4.6 nodejs-mobile 内置 Node 版本低于 26，server 报 “xxx is not a function / API 不存在”
**原因**：BLUEPRINT 已标注此风险——PC 上用 Node 26 构建，但端内 nodejs-mobile 运行时可能更低，导致 server 用到的新 API 缺失。
**解决**：
1. 先确认 nodejs-mobile 实际内置版本；
2. 对缺失 API 做 polyfill，或 `package.json` 的 `engines`/依赖降级到兼容版本；
3. 兜底：**模式 A 远程**，端内不跑 Node。

### 4.7 `pnpm: 无法将“pnpm”项识别为 cmdlet...`
**解决**：脚本会自动 `corepack enable` 或 `npm i -g pnpm`；若仍失败，手动 `npm install -g pnpm` 后重开终端。

### 4.8 aria2 下载 404 / deb 解包失败 / 找不到 `tar`
- Google/Termux 版本号会变，`fetch-aria2-android.ps1` 已给多条候选；全失败时到 `https://packages.termux.dev/apt/termux-main/pool/main/a/aria2/` 手动取最新 `*_aarch64.deb` / `*_arm.deb`，再用 `-LocalArm64/-LocalArmv7` 落地。
- 解 `.deb` 用 Windows 自带 `tar.exe`；若报错，用 7-Zip 解出 `data.tar.*` 再解，里面 `.../usr/bin/aria2c` 即目标文件。
- 端内运行报「Permission denied」：App 启动时需把 `nativeLibraryDir/libaria2c.so` `chmod 0o755`（安卓侧代码负责）。

### 4.9 `gradlew.bat` 报权限/换行符错误
`gradlew.bat` 若是 CRLF 无关；Linux 下才需 `chmod +x`。Windows 直接 `.\gradlew.bat`。首次会下载 Gradle 发行包，慢属正常。

### 4.10 构建内存不足 / 卡在 `:app:mergeDex`、`transformClassesWithDex`
**解决**：`android\gradle.properties` 里调 `org.gradle.jvmargs=-Xmx4g -XX:MaxMetaspaceSize=1g`，关闭并行 `org.gradle.parallel=false` 试试；关掉杀软实时扫描项目目录。

## 5. 产物与复现性

| 产物 | 位置 |
|---|---|
| APK | `android\app\build\outputs\apk\debug\app-debug.apk` |
| 前端静态站 | `android\app\src\main\assets\renderer-web\` |
| 后端 | `android\app\src\main\assets\nodejs-project\dist-server\` |
| aria2c | `third_party\aria2\<abi>\aria2c` 与 `android\app\src\main\jniLibs\<abi>\libaria2c.so` |
| aria2 来源/许可证 | `third_party\aria2\NOTICE.md` + `manifest.json` |
| 构建日志 | `reports\build-all-<时间戳>.log` |

**可复现要点**：
- 全部步骤脚本化，无手工隐式步骤；依赖在 `pnpm-lock.yaml` 锁定，SDK 包版本在脚本里固定。
- 干净环境 = 新 Windows + Node LTS + 跑一次 `install-toolchain.ps1` + `build-all.ps1`。
- 想完全离线复现：预先把 JDK17 安装包、cmdline-tools zip、SDK 组件、aria2c 都备到本地，再改脚本走本地路径。

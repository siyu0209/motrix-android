# 08 · 渲染器接口契约（Renderer ⇄ Server Interface Contract）

> 归属：程序逆向分析 + 程序审计（reverse-auditor）
> 源码基线：`projects/src-motrix/Motrix-main`（Motrix Turbo v2.4.3）
> 取证方式：只读 TS 源码，三处交叉印证——`src/shared/protocol/**`（通道权威定义）+ `src/server/http/**`（HTTP/WS 传输与鉴权）+ `src/server/ipc/**`（服务端 handler 的实现与 payload）。
> 标注约定：✅=源码直证；🟡=推断（源码未直读该实现/字段）；❌=源码明确不支持。

---

## 0. 结论先行（TL;DR）

1. **只有一种 web/安卓传输路径**：`renderer → HttpWsTransport → server`。
   - 命令/查询：`POST {base}/rpc/{command|query}/<channel>`，请求体 `{ "args": [...] }`，响应 `application/json`（`JSON.stringify(value ?? null)`）。
   - 事件：`GET {base}/rpc/events`（WebSocket），JSON 帧 `{ "channel": "...", "args": [...] }` + 心跳。
   - ✅ 证据：`src/server/http/app.ts:267-337`（路由 + dispatchCommand）、`:80-84`（sendRpcValue）、`src/renderer/lib/transport/http-ws.ts:146-181`（invoke）、`:270`（wsUrl）、`:334-367`（帧分发）。
2. **基址 = 同源 `location.origin + pathname`，没有独立的“远程服务器地址”配置项**。所以：模式A（远程）也必须让 WebView 直接导航到 server 自身托管的 Web UI，renderer 才能把 RPC 打到同源 `/rpc/*`。
   - ✅ `src/renderer/lib/web-base-url.ts:8-18`、`src/renderer/lib/transport/index.ts:6-9`。
3. **通道名一律来自 `src/shared/protocol/`，禁止裸字符串**。三张枚举体量：**Commands 128 条 / Queries 75 条 / Events 81 条**，另有 Bridge 三类（扩展配对）。本文第 5 节逐条列出。
4. **鉴权是 operator token 门（deny-by-default）**，作用于 `/rpc/*`、`/api/*`、`/rpc/events`；cookie 名 `mtx_op`（HttpOnly, SameSite=Strict, 7 天），登录接口 `POST /rpc/auth/login {token}`。**`/healthz`、静态 SPA 壳、auth 三接口是公开的**。
   - ✅ `src/server/http/operator-auth.ts:172-188,272-423`。
5. **引擎 = 外部 aria2 子进程**，所有任务动作在 server 侧转成 aria2 JSON-RPC（`ws://127.0.0.1:<port>/jsonrpc`）。渲染器**从不**直连 aria2；它只调用本文枚举的 `command:*` / `query:*`。第 6 节给出完整映射。
   - ✅ `src/core/engine/aria2/aria2-rpc-client.ts`、`src/core/engine/aria2/aria2-adapter.ts`。
6. **桌面专属通道在 web 模式是 no-op 或返回不支持**：渲染器健康探测在 `__MOTRIX_TARGET__==='web'` 时直接 return；`GetCliToolStatus`/`GetAppImageIntegrationStatus` 等返回 “unsupported” 常量。安卓 MVP 无需实现。
   - ✅ `src/renderer/lib/renderer-health.ts:76`、`src/server/ipc/queries.ts:210,304`。

## 1. 渲染器如何定位 server（基址解析）

### 1.1 目标判定
✅ `src/renderer/lib/transport/index.ts:6-11`
```ts
export function createTransport(): Transport {
  if (__MOTRIX_TARGET__ === 'electron') return new ElectronTransport()
  return new HttpWsTransport(webBaseUrl())
}
export const transport = createTransport()
```
- 构建期 `__MOTRIX_TARGET__` 由 vite define 注入：web/安卓渲染构建为 `'web'`（✅ `vite.renderer.web.config.ts` 的 `define`），桌面为 `'electron'`。
- web 分支拿到的是 `HttpWsTransport(webBaseUrl())`——**基址在创建 transport 时一次性解析**。

### 1.2 基址公式
✅ `src/renderer/lib/web-base-url.ts:8-18`
```ts
export function webBaseUrl(location = globalThis.location) {
  const pathname = location.pathname
    .replace(/\/index\.html$/, '/')
    .replace(/\/$/, '')
  return `${location.origin}${pathname}`
}
```
- 结论：`base = origin + 去尾斜杠(pathname)`；`index.html` 结尾会被抹平。
- 无 query、无 localStorage、无 `<meta>` 覆盖——**不存在“填个服务器地址”的运行时配置**。
- 允许部署在子路径：配合服务端 `MOTRIX_WEB_BASE_PATH`（✅ `src/server/http/web-base-path.ts`；注入点 `src/server/index.ts:1546`）。

### 1.3 对移植的关键约束
- ✅ **模式B（端内内嵌）**：server 与 WebView 天然同源 `http://127.0.0.1:<port>`，基址解析成立。
- ✅ **模式A（远程遥控）**：WebView 必须 `loadUrl(serverBase)` 加载 server 托管的 `dist/renderer-web`，且 cookie 会话随同源生效；**不能**用一个本地壳页面去跨域 `fetch` 远端 `/rpc/*`（会触发 CSRF/Origin 校验，见 §3）。
- 🟡 若产品非要“壳页面 + 动态填服务器地址”，等价于要改 renderer 传输层（新增可配置 base），属**受限改造**，不在原样复用范围。

## 2. HTTP JSON-RPC 契约（传输层）

### 2.1 客户端请求构建（权威实现）
✅ `src/renderer/lib/transport/http-ws.ts`
- invoke（`:146-181`）：
  - `kind = rpcKindFor(channel)`：`command:` 前缀→command，`query:` 前缀→query，Bridge 成员查 `BridgeCommands/BridgeQueries`，兜底 query（`:47-53`）。
  - `POST ${baseUrl}/rpc/${kind}/${encodeURIComponent(channel)}`（`:147`）
  - 头：`content-type: application/json`；NAS 模式追加 `x-motrix-web-origin: location.origin`（`:149-156`，`webOriginHeaders()`）。
  - `credentials: 'same-origin'`（`:156`）；`body: JSON.stringify({ args })`（`:157`）。
  - query 类带 `signal: AbortSignal.timeout(15_000)`（`:159`）。
  - `res.status === 401 → refreshOperatorSession()`（`:162`）；`!res.ok` 抛 `rpc failed ${status}: ${text}`；成功 `res.json()`。
- 注意：**参数是位置数组**，不是命名对象。渲染器 `invoke(channel, ...args)` 直接展开成 `args`。

### 2.2 服务端路由与分发
✅ `src/server/http/app.ts`
| 路由 | 方法 | 说明 | 证据 |
|---|---|---|---|
| `/rpc/command/:channel` | POST | 命令面；无 handler → 404 `{error:'unknown channel'}` | `:267-270`、`:208-260` |
| `/rpc/query/:channel` | POST | 查询面；`GetTaskInspectorActivity` 走共享协议信封 `makeProtocolSuccess/Failure` | `:272-337` |
| `/rpc/events` | GET(WS) | 事件流（需 `eventBus`） | `:353-377` |
| `/healthz` | GET | `healthCheck()`→200/503（公开） | `:203-206` |
| `/*` | GET | `fastifyStatic` 挂 `rendererDir`；SPA fallback 返回 `index.html` | `:380-402` |

分发细节（✅ `:208-260`）：
- `handler = commandHandlers[channel] ?? bridgeCommands[channel]`；缺失 404。
- 目录类命令经 `directoryRpc`，body 必须是 `{args:[单个]}`，返回 `{ok:false,error:{code}}`。
- `OPERATION_CHANNELS`（插件操作 10 条，见 `src/shared/protocol/operation-channels.ts:2-13`）的 handler 以 `(owner, args[0])` 调用，未认证 401。
- 其余 `handler(...(req.body?.args ?? []))`。
- **响应统一** `sendRpcValue = reply.type('application/json').send(JSON.stringify(value ?? null))`（`:80-84`）——即返回 `null` 而非空体。

### 2.3 大体积 torrent 上传（旁路大 body 路由）
✅ `src/server/http/torrent-command-routes.ts`
- 默认 RPC body 上限 `2 MiB`；`CreateTask` / `AddTorrentTask` 单开大 body 路由，上限 2–64 MiB，并发 `MAX_LARGE_REQUESTS=2`，超并发 429 `Too many large torrent requests`。
- 两种信封：`createTorrentEnvelope = {args:[{type:'bt',payload:{kind:'torrent-base64',base64}}]}`；`addTorrentEnvelope = {args:[{base64}]}`（`:20-33`、`:102-131`）。

### 2.4 其余 `/api/*` 控制面（受同一 operator 门保护）
✅ 真路由（非 RPC，直接 REST）：
- `GET /api/diagnostics`（`src/server/routes/diagnostics.ts:7`）
- `POST /api/plugins/uploads`（`src/server/routes/plugin-uploads.ts:26`）
- `POST /api/tasks/pause-all`、`POST /api/tasks/resume-all`（`src/server/routes/tasks-bulk.ts:18,23`）
- fnOS：`POST /api/fnos/directory`、`/api/fnos/task-path`、`/api/fnos/torrent`（`src/server/platform/fnos/routes.ts:25,34,60`）
- NAS：`/api/nas/tasks/:id/file`、`/api/nas/torrent`（`src/server/platform/nas/file-routes*`）
> 说明：`/api/tasks/*` 也属控制面（✅ `operator-auth.ts:23` 注释与 `:274` 门控）。安卓 MVP 可只用 `/rpc/*`，不依赖 `/api/*`。

## 3. 鉴权与会话（Operator Auth）

✅ 全部来自 `src/server/http/operator-auth.ts`（466 行）。另有前端消费 `src/renderer/lib/operator-auth.ts`。

### 3.1 门控模型
- deny-by-default：`onRequest` 拦截 `/rpc/*`、`/api/*`、`/rpc/events`（`:272-321`）。
- 响应加 `cache-control: no-store` + `pragma: no-cache`。
- CSRF：非 GET 且带 `Origin` 必须与 host 同源，否则 403 `cross-origin forbidden`。
- WS：未认证 401/429；已 cookie 认证但 `Origin ≠ expectedBrowserOrigin` → 403。
- `expectedBrowserOrigin` = `MOTRIX_PUBLIC_URL` 的 origin，否则 `${https?}://${Host}`（`:115-131`）。

### 3.2 公开端点（`isPublic`，`:172-188`）
- `GET /healthz`
- `POST /rpc/auth/login`
- `GET /rpc/auth/status`
- 以及「GET 且非 `/rpc/`、非 `/api/`」的静态 SPA 壳资源。

### 3.3 认证接口
| 接口 | 请求 | 响应 | 证据 |
|---|---|---|---|
| `POST /rpc/auth/login` | `{ token }` | 成功 Set-Cookie `mtx_op=<随机32B base64url>; HttpOnly; SameSite=Strict; Path=/; Max-Age=<7d>; (Secure if https)` → `{ok:true}`；失败 401 `invalid token` / 429 | `:324-347` |
| `POST /rpc/auth/token` | `changeOperatorTokenSchema`（bodyLimit 16384；需 bearer 或精确 Origin；仅 `tokenSource==='file'`） | `{ok:true}` \| `{ok:false,reason:'incorrectToken'\|'invalid'\|'managed'\|'rateLimited'\|'unavailable'}` | `:349-387` |
| `GET /rpc/auth/status` | — | `OperatorStatus{authed, mode, canLogout, tokenSource?, clientPairing?, eventOriginMatches?}` | `:389-413` |
| `POST /rpc/auth/logout` | — | 清 cookie `{ok:true}` | `:415-423` |

- `mode ∈ ['cookie','bearer','unrestricted','unauthenticated','fnosGateway','synologyDsm']`（✅ `src/shared/schemas/operator-auth.ts`）。
- 登录限流：`LOGIN_WINDOW_MS=60000`、`LOGIN_MAX=20`（`:26-29`）。
- `principal(req)`：bearer→`bearer:<sha256(token)hex>`，cookie→`session:<sha256(id)hex>`；`bindSocket` 按会话跟踪 socket 以便吊销（`:425-465`）。

### 3.4 token 来源
✅ `src/server/operator-token.ts`：`MOTRIX_OPERATOR_TOKEN` 优先，否则随机 32 字节 base64url 写 `<dataDir>/operator-token`（0600）。

### 3.5 前端消费
✅ `src/renderer/lib/operator-auth.ts`：`refreshOperatorSession` 轮询 `/rpc/auth/status`（带 `x-motrix-web-origin`），`authed:false → locked()`；`operatorLogin(token)` 走 `POST /rpc/auth/login`；解锁屏 `src/renderer/components/operator-unlock-gate.tsx`。
> 移植注意：**嵌入式模式需要拿到 `<dataDir>/operator-token` 并自动登录**（原生侧读取后经 JS 桥/自动 POST 注入），否则 WebView 会停在解锁屏。这条是模式B 的必经集成点（详见 §8）。

## 4. WebSocket 事件流

✅ `src/server/http/events.ts`、`src/server/http/event-heartbeat.ts`、`src/shared/schemas/web-event-stream.ts`、`src/renderer/lib/transport/http-ws.ts:232-367`。

### 4.1 连接
- URL：`${base.replace(/^http/,'ws')}/rpc/events`（✅ `http-ws.ts:270`）。
- 连接超时 `WEB_EVENT_CONNECT_TIMEOUT_MS=10000`。
- fnOS 模式：先 `POST {base}/rpc/auth/event-ticket` 拿 ticket，用子协议 `[FNOS_EVENT_PROTOCOL='motrix.fnos.events', FNOS_EVENT_TICKET_PREFIX+'<ticket>']` 升级（✅ `:232-255`）。
- 重连退避：`[250,500,1000,2000,5000,10000] ms`（`:61`）。

### 4.2 帧类型（服务端 → 客户端）
| type | 结构 | 说明 | 证据 |
|---|---|---|---|
| 数据帧 | `{ channel: string, args: unknown[] }` | `webEventFrameSchema`；客户端按 `channel` 找监听器 `cb(...args)` | `web-event-stream.ts` / `http-ws.ts:351-363` |
| 心跳 | `{ type:'heartbeat', version:1 }` | 服务端每 `WEB_EVENT_HEARTBEAT_MS=15000` 发一次 + `ws.ping()`；超 `WEB_EVENT_STALE_MS=45000` 无 pong → terminate | `event-heartbeat.ts:10-36` |
| 会话续期 | `{ type:'session-renewal', version:1, challenge }`（synologyDsm） | 客户端回 `POST /rpc/auth/event-renew`（body=frame） | `http-ws.ts:304-316` |

- 广播实现：`bindEventBroadcaster(bus)` 订阅 forwardable events，逐 socket `JSON.stringify({channel,args})`；发送失败 terminate（✅ `events.ts:39,46-58`）。

### 4.3 客户端订阅语义
- `transport.on(channel, cb)` / `off(channel, cb)`；事件名用 `Events.*`（如 `event:taskUpdated`）。
- 插件日志为**后缀通道**：`event:pluginLog:<pluginId>`（✅ `src/shared/protocol/events.ts:104-108`）。
- 会话状态联动：`locked → stopSocket`，`authenticated → ensureSocket`（✅ `http-ws.ts:105-112`）。

## 9. 安卓端集成注意（与接口契约直接相关）

1. **基址同源铁律**：WebView 必须 `loadUrl(server 托管的 Web UI)`，不能另起本地壳去跨域打 `/rpc/*`（CSRF/Origin 校验会 403）。✅ §1、`operator-auth.ts:272-321`。
2. **自动登录**：嵌入式启动后，原生侧需读取 `<dataDir>/operator-token` 并替用户完成 `POST /rpc/auth/login`（或前端注入 `operatorLogin(token)`），否则停在解锁屏。✅ §3.5。
3. **端口契约要打通**：`main.js` 当前注入 `process.env.MOTRIX_PORT`，而 server 监听读 `process.env.PORT`（✅ `src/server/index.ts:2053-2064`）→ 需在宿主层桥接或改为注入 `PORT`。`MOTRIX_ARIA2_PATH` 也应改为 `MOTRIX_ARIA2_BIN`（✅ `src/server/platform/services.ts:44-70`）。
4. **WS 心跳**：安卓省电/切网会杀 socket；按 `15000ms` 心跳、`45000ms` 失活、指数退避 `[250…10000]` 的语义实现重连（server 侧已内建心跳，客户端只需正确处理 `{type:'heartbeat'}` 与重连）。✅ §4。
5. **大 torrent 上传**：BT 文件动辄 >2MiB，必须走 `CreateTask` 大 body 路由（≤64MiB，并发 2）；超并发会 429。✅ §2.3。
6. **slim 与全量的分野**：列表页用 `ListTasks`（slim），单任务详情页再拉 `GetTaskDetail`（全量含 trackers）——不要在列表页强求 `bt.trackers`。✅ §6.3。

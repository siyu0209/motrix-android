## 0. 结论先行（给 Lead 的一页纸）

1. **架构判定**：Motrix 是「**React 渲染层（dist/renderer-web） ↔ HTTP JSON-RPC + WebSocket ↔ Fastify 服务端（dist/server）+ core 引擎（aria2 子进程 / ffmpeg 子进程）**」的标准 client-server 结构，渲染层与服务端**天然解耦**，且 `src/core/` 强制 host-neutral（`CLAUDE.md`「Architecture Boundaries」：*`src/core/` never imports `electron` or `src/main/`*）。→ **安卓端无需 Electron，只需「WebView + 本机 Node 后端 + aria2c 二进制」**，双模方案（见 docs/02）成立。
2. **真正难移植的只有 3 个原生/外部件**（其余全是纯 JS/WASM，可直接跑）：
   - `better-sqlite3`（C++ 原生模块，`src/core/session/motrix-database.ts:28-30`）→ 需 NDK 交叉编译或纯 JS 兜底（**头号硬骨头 R1**）。
   - `aria2c`（外部可执行二进制，非 npm，`src/server/platform/services.ts:44-70`）→ 需安卓 arm64-v8a/armeabi-v7a 二进制（**R4**）。
   - `nodejs-mobile` 内置 Node 版本 vs 服务端要求（`vite.server.config.ts` target `node22`）→ 版本必须核对（**R3**）。
3. **渲染层零改造可复用**：renderer 通过 `@renderer/lib/transport` 抽象访问后端，Web 模式下走 `HttpWsTransport(webBaseUrl())`（`src/renderer/lib/transport/index.ts:6-9`），**只认同源**；因此后端必须由 server 自身托管 Web UI，WebView 直接导航到该 URL 即可，不需改协议。
4. **认证是必须补的一环（现状脚手架缺失）**：控制面 `/rpc/*`、`/api/*`、`/rpc/events` 默认**拒绝一切**，仅放行 `/healthz`、`/rpc/auth/login`、`/rpc/auth/status` 与「非 `/rpc`/`/api` 的静态 GET」（`src/server/http/operator-auth.ts:170-188,272-321`）。渲染层有 `OperatorUnlockGate` 解锁屏（`src/renderer/components/operator-unlock-gate.tsx:34,130-160`），需输入 **operator token**（`MOTRIX_OPERATOR_TOKEN` 或 `<dataDir>/operator-token`，`src/server/operator-token.ts:36-61`）登录换取 httpOnly SameSite=Strict cookie。**当前 `MainActivity.loadApp()` 直接 `loadUrl(base)`，未做登录注入 → 必然停在解锁屏**（详见 §8 P0-3）。
5. **引导脚本 `main.js` 与 server 存在 4 处契约不一致**（变量名/路径/hook），会导致「端口不生效、aria2 路径不生效、ready 文件找不到、关闭不优雅」——已在 §8 P0-4 与 docs/02 §5 列成「必须改」清单。

## 2. 分层与边界（决定「能复用多少」）

目录：`src/{core,main,preload,renderer,server,shared,test-utils}`、`packages/`、`scripts/`、`docs/`。

`CLAUDE.md`「Architecture Boundaries」硬规则（对本移植极其有利）：
1. `src/core/` 永不 import `electron` / `src/main/` → **core 可整包搬到安卓 Node 运行时**。
2. `src/renderer/` 永不 import `core`/`main`/`server`，只经 `@renderer/lib/transport` + 共享协议常量（`src/shared/protocol/`）→ **renderer 换宿主零改**。
3. `src/shared/` 只放纯跨层契约与描述数据（无 IO/定时器/网络/Electron/Node API）。
4. 通道名只用 `Commands/Queries/Events` 及 `Bridge*` 常量，禁用裸字符串。

→ **结论**：Android 版可以**最大程度复用 core + server + renderer 三块源码**，移植工作量集中在「宿主环境（Node/aria2/文件系统/认证/通知）」而非业务逻辑。

## 3. 前后端交互协议（移植的契约核心）

### 3.1 命令/查询：HTTP JSON-RPC
- `POST /rpc/command/:channel`（命令，写）、`POST /rpc/query/:channel`（查询，读）。
- 请求体 `{ args: [...] }`，响应 `application/json`。
- 证据：`src/server/http/app.ts:267-337`（路由注册与 `dispatchCommand`）、`:208-260`（分发逻辑）。
- 客户端封装：`src/renderer/lib/transport/http-ws.ts:146-181`（`invoke`）。

### 3.2 事件：WebSocket
- `GET /rpc/events`，服务端推送 JSON 帧 `{ channel, args }` + 心跳；客户端 `wsUrl = baseUrl.replace(/^http/,'ws') + '/rpc/events'`。
- 证据：`src/server/http/app.ts:339-378`；`src/renderer/lib/transport/http-ws.ts:270`、`:334-367`（message 分发）。

### 3.3 基址选择：只认同源
- `webBaseUrl()` = `location.origin + pathname`（`src/renderer/lib/web-base-url.ts:8-18`）。
- 传输选择：`__MOTRIX_TARGET__==='electron'`→ElectronTransport；否则 `new HttpWsTransport(webBaseUrl())`（`src/renderer/lib/transport/index.ts:6-9`）。
- **推论**：renderer **没有「远程服务器地址」配置项**。模式 A（远程）要成立的唯一方式是：WebView 直接导航到「远端 server 自身托管的 Web UI」，让页面 origin == server origin。这是 docs/02 双模方案的基石。

### 3.4 认证：operator token（控制面网关）
- 默认拒绝 + 白名单：`/healthz`、`POST /rpc/auth/login`、`GET /rpc/auth/status`、以及「非 `/rpc`/`/api` 的 GET（静态 SPA 壳与资源）」（`src/server/http/operator-auth.ts:170-188`）。
- 登录：`POST /rpc/auth/login` body `{ token }` → 校验通过下发 `mtx_op`（HttpOnly、SameSite=Strict、Path=/、TTL 7 天）cookie（`operator-auth.ts:324-347`）；脚本类客户端可用 `Authorization: Bearer <operatorToken>`（`operator-token.ts:105-109`；Basic 空用户名兼容含空格口令）。
- 服务端开关：`createApp({ operatorAuth: { operatorToken, tokenSource, publicUrl, ... } })`（`src/server/index.ts:1561-1572`）；NAS/fnOS 模式 `operatorAuth: undefined` 走 ticket+`WEB_ORIGIN_HEADER` 另一套（`index.ts:1561-1562`）。
- token 来源：`MOTRIX_OPERATOR_TOKEN` 环境变量优先，否则随机 32 字节写 `<dataDir>/operator-token`（0600）（`src/server/operator-token.ts:36-61`）。
- 渲染层：`refreshOperatorSession()` 轮询 `/rpc/auth/status`，`authed:false` 即 `locked()`→显示 `OperatorUnlockGate`；`operatorLogin(token)` POST `/rpc/auth/login`（`src/renderer/lib/operator-auth.ts:59-106,137-162`）。
- WS 事件安全：cookie 认证的 upgrade 必须 `Origin === expectedBrowserOrigin`（`publicUrl` 或 `Host` 头推导，`operator-auth.ts:115-141,309-320`）→ **模式 A 若经反代/域名访问，服务端必须设 `MOTRIX_PUBLIC_URL` 且与手机访问 origin 一致，否则事件 WS 被 403**。

> 注意区分：**operator token（Web 控制面）** 与 **MDXP 配对/agent token（浏览器扩展、CLI、bridge，`docs/bridge-pairing-protocol.md`、`src/core/bridge/*`、`src/server/bridge/*`）** 是两套独立凭证。BLUEPRINT §二把模式 A 描述成「填 URL + bridge 配对」并不准确——**Web UI 远程访问真正需要的是 operator token 登录**，MDXP 配对是给扩展/CLI/agent 的另一条通道。

## 7. 可还原性分级清单（以「安卓端能否还原」为准）

> 分级口径与 docs/00 一致：**L1 完整还原 / L2 近似还原 / L3 替代 / L4 不可还原（不支持）**。

| 能力 | 分级 | 说明与依据 |
|---|---|---|
| 渲染层 UI（任务列表/设置/统计等） | **L1** | WebView 加载同一 `dist/renderer-web`，协议同源不变（§3.3） |
| HTTP/HTTPS/FTP 下载 | **L1** | aria2 原生能力；安卓需 aria2c 二进制（§6） |
| BT 下载 | **L1** | aria2 原生 BT |
| 磁力（magnet） | **L1** | aria2 + torrent 解析 |
| 任务管理（增/删/暂停/继续/重试/批量） | **L1** | 逻辑全在 server（§4），与宿主无关 |
| 限速（全局/单任务） | **L1** | aria2 参数 |
| 统计 | **L1** | server 计算后下发 |
| 设置与持久化 | **L2（条件）** | 依赖 better-sqlite3；交叉编译失败则降 L3（纯 JS/JSON 兜底）或依赖远端 |
| 系统通知（完成/出错） | **L2** | 安卓通知渠道（需 `POST_NOTIFICATIONS`） |
| 协议唤起（magnet/.torrent） | **L2** | Android Intent Filter（`MainActivity.handleIntent` 已接 magnet） |
| 系统代理 | **L2** | 应用内 aria2 代理为主，系统级代理受限 |
| 多窗口/设置窗 | **L3** | 单 WebView + SPA 路由/弹层 |
| 剪贴板自动识别 | **L3** | Android 10+ 后台读剪贴板受限，前台/手动粘贴 |
| 阻止休眠 | **L3** | 前台服务 + WakeLock（厂商 ROM 仍需白名单） |
| 托盘 | **L4** | 无托盘，前台常驻通知替代 |
| 自动更新 | **L4** | 手动机场/商店更新 |
| 插件系统 | **L3/L4** | WASM 沙箱可跑，但插件注册/权限/hook 与桌面路径假定不同，非核心，先不保证 |
| MDXP 扩展配对/bridge | **L4（端内）** | 手机无桌面扩展宿主；如需，作为「远程客户端」能力的一部分 |

### P0 · 阻塞「模式 B 端内内嵌」跑通

### 8.1 P0-4 契约不一致逐条（`main.js` → `dist/server`）
| # | `main.js` 现状 | server 实际读取 | 后果 | 修正 |
|---|---|---|---|---|
| a | 设 `process.env.MOTRIX_PORT = port`（`main.js:292`） | 监听端口只读 `process.env.PORT`（`src/server/index.ts:2053`） | **server 仍监听默认 8080**，与握手端口 16800 不符，WebView 连错端口 | 改为设 `process.env.PORT = String(port)`（或同时设） |
| b | 注入/提示 `MOTRIX_ARIA2_PATH`（`main.js:146-152`） | 只认 `MOTRIX_ARIA2_BIN`（`services.ts:69-70`） | aria2 二进制路径被忽略，回落到 `/usr/bin/aria2c`（安卓不存在）→ 引擎启动失败 | 改设 `MOTRIX_ARIA2_BIN` |
| c | 设 `MOTRIX_DOWNLOAD_DIR`（`main.js:107-115,132`） | server 不消费该变量；下载目录来自 `settings.defaultSaveDir` / 任务参数 | 下载目录不会自动生效 | 由首启写入 settings，或经命令通道设置 `defaultSaveDir` |
| d | 设 `MOTRIX_HOST`（`main.js:61,133`） | server 固定 `host:'0.0.0.0'`（`index.ts:2053-2064`） | 变量被忽略（安卓上 0.0.0.0 也仅本机可达，风险可控但需知悉） | 无需改；如需仅回环，另加收紧（慎） |

> 额外（同属集成层，见下 P1-1）：`MotrixServerService` 用 `Class.forName(...).startNodeWithArguments(["node", mainJs])` 起 Node（`MotrixServerService.kt:52-55`），**该 API 不注入自定义环境变量**；`main.js` 依赖的 `MOTRIX_DATA_DIR` 等需由原生侧以「命令参数/引导 JSON 文件」方式传入，否则 `DATA_DIR` 会退到 `HOME`/`tmp`，与 `MainActivity` 轮询的 `filesDir/motrix-ready.json`（`MainActivity.kt:166`）不一致 → **握手文件读不到**。修正：把 `DATA_DIR` 设为 `filesDir` 并经参数/配置文件传给 `main.js`，两侧统一路径。

## 9. 优化空间（可回收的红利）

1. **`src/core` host-neutral** → 直接复用任务/引擎/DB/插件全部业务代码，安卓只需换「PlatformServices 实现 + aria2 二进制 + Node 运行时」（见 docs/02 §6）。
2. **renderer 走 transport 抽象** → 移动端零协议改造；仅注入 CSS/JS 做适配（`MainActivity.injectOverrides` 已实现，`MainActivity.kt:180-191`）。
3. **同源托管** → WebView 直接连 server 自身 UI，省去跨域/基址配置（§3.3）。
4. **服务端已支持子路径** `MOTRIX_WEB_BASE_PATH`（`src/server/index.ts:1546`、`web-base-path.ts`）→ 便于未来反向代理/多实例。
5. **认证已内建** → 只需补「token 自动登录注入」，无需自造会话体系。

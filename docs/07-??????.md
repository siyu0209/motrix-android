## 2. 两种模式各自的二次开发

两个模式是同一个 App 的两个 **product flavor**（定义在 `android/app/build.gradle.kts:22-33`）：

| flavor | 编译开关 | 含义 | 原生依赖 |
|---|---|---|---|
| `remote` | `EMBEDDED_SUPPORTED=false` | 薄客户端，WebView 连外部 Motrix server | **零原生依赖，开箱可编最稳** |
| `embedded` | `EMBEDDED_SUPPORTED=true` | 端内内嵌，nodejs-mobile 跑 dist-server + 安卓 aria2c | 需 nodejs-mobile aar + aria2c + dist-server |

### 2.1 远程模式（remote）怎么改

- 入口逻辑在 `MainActivity.onCreate`（`MainActivity.kt:61-66`）：有保存地址直接连；否则显示 setup 面板。
  面板按钮接线在 `wireSetupPanel()`（`:126-141`）：`btnConnect` 读 `serverUrl` → 规范化补 `http://`、去尾 `/` → 存 `Prefs` → `loadApp()`。
- **要支持"扫码/预置服务器/多服务器切换"**：改 `wireSetupPanel()` 与 `Prefs.kt`（新增 key）、对应 `res/layout/activity_main.xml`。
- **不需要**碰 aria2 / nodejs-mobile / dist-server。
- 构建：`gradle assembleRemoteDebug`（产物 `app/build/outputs/apk/remote/debug/`）。

### 2.2 端内内嵌模式（embedded）怎么改

这条链是三个进程接力，改哪一环先看时序：

```
MainActivity.startEmbeddedAndLoad()            # MainActivity.kt:156-163
   └─ startForegroundService(MotrixServerService)
        └─ MotrixServerService.startNodeBridge()   # 反射 NodeJS.startNodeWithArguments(["node", main.js])
             └─ assets/nodejs-project/main.js      # 读 env → chdir → import ./dist-server/index.mjs
                  └─ Fastify server 监听 127.0.0.1:<port>
   └─ MainActivity.pollReadyFile()             # 轮询 filesDir/motrix-ready.json 取真实 port → loadUrl
```

- **准备条件**（缺一不可）：① `dist-server/` 已 stage 进 `assets/nodejs-project/`；② 把 nodejs-mobile 的 `aar` 放到 `android/app/libs/`，并取消 `app/build.gradle.kts:70` 那行 `embeddedImplementation(files("libs/nodejs-mobile.aar"))` 注释；③ `aria2c` 已 stage 成 `jniLibs/<abi>/libaria2c.so`。
- **改引导逻辑**：几乎都在 `assets/nodejs-project/main.js`（读环境变量、切目录、找空闲端口、写握手、优雅退出、兜住 better-sqlite3 失败）。
- **改启动方式/参数注入**：`MotrixServerService.startNodeBridge()`（`MotrixServerService.kt:49-60`）。注意：`startNodeWithArguments` **不会注入自定义环境变量**，运行参数必须走 argv 或旁路配置文件（见 §7 坑3）。
- 构建：`gradle assembleEmbeddedDebug`（产物 `app/build/outputs/apk/embedded/debug/`）。

> ⚠️ 端内模式是"实验/攻坚"路径，better-sqlite3 交叉编译、nodejs-mobile 内置 Node 版本是两大硬骨头，未打通前先以 remote 模式交付可用版本（详见 `docs/04` R1/R3）。

## 3. 扩展 JS 原生桥 `window.MotrixAndroid`

桥是 WebView 页面与原生通信的唯一入口，当前暴露 6 个方法（`MotrixJsBridge.kt`）：

| 方法 | 返回 | 作用 |
|---|---|---|
| `onBack()` | Boolean | 页面请求返回/退出（回调到 `MainActivity.handleBackFromWeb()`） |
| `getServerBase()` | String | 取真实后端基址（模式B 用握手端口，勿写死） |
| `pickDownloadDir()` | void | 拉起 SAF 目录选择器，选中后存 `Prefs.dl_tree` |
| `toast(msg)` | void | 原生轻提示 |
| `getStatus()` | String(JSON) | 运行状态：`{mode, serverBase, embeddedSupported}` |
| `addUrl(url)` | void | 把 magnet/链接派发给页面：`window` 上 `CustomEvent('mtx:add-url',{detail:url})` |

### 3.1 新增一个桥方法的完整步骤

以"取设备存储信息 `getStorageInfo()`"为例：

1. **`MotrixJsBridge.kt` 加注解方法**（返回类型限 String/基本类型，复杂数据用 JSON 字符串）：
   ```kotlin
   @JavascriptInterface
   fun getStorageInfo(): String = activity.storageInfoJson()
   ```
2. **`MainActivity` 实现 handler**（涉及 UI 的用 `runOnUiThread`；耗时计算别放主线程）：
   ```kotlin
   fun storageInfoJson(): String {
       val o = org.json.JSONObject()
       val stat = android.os.StatFs(filesDir.path)
       o.put("freeBytes", stat.availableBytes); o.put("totalBytes", stat.totalBytes)
       return o.toString()
   }
   ```
3. **页面侧调用**（`renderer-overrides/mobile-adapt.js` 或注入脚本里）：
   ```js
   const info = JSON.parse(window.MotrixAndroid.getStorageInfo());
   ```

### 3.2 反向：原生 → 页面

仿 `addUrl` 用 `webView.evaluateJavascript("window.dispatchEvent(new CustomEvent('自定义事件',{detail:...}))")`。页面 `document.addEventListener('自定义事件', e => ...)` 接收。**所有 `evaluateJavascript` 都要在主线程**（桥里已用 `runOnUiThread`）。

### 3.3 安全要求（红线，见 `docs/00` A10）

- 只暴露**白名单**方法，不暴露通用 `loadUrl`/`exec` 之类。
- 入参做校验（如 `addUrl` 只接受 `http(s)://`、`magnet:`、`ftp:` 前缀）。
- 返回给页面的数据不含 token/密钥明文；敏感值查询单独设计、可鉴权。

## 4. 移动端 CSS/JS 注入点

- **源文件**：`renderer-overrides/mobile-adapt.css` + `mobile-adapt.js`（改样式/交互就改这里，这是唯一源头）。
- **运行期副本**：`android/app/src/main/assets/mobile-adapt.css|js`。App 在 `MainActivity.injectOverrides()`（`MainActivity.kt:180-191`）里从 assets 读出文本、`evaluateJavascript` 注入到页面（CSS 包成 `<style>`、JS 直接执行）。**改完 `renderer-overrides/` 要同步覆盖到 `assets/`**，否则 App 里看不到变化。
- **总开关**：所有规则挂在 `html.mtx-mobile` 下，去掉即完全恢复原站；分项开关见 `renderer-overrides/README.md` 第五节。
- **钩子约定**：给 DOM 加 `data-mtx-*`（如 `data-mtx-dialog`、`data-mtx-bottom-bar`、`data-mtx-reflow="single"`）即可获得对应适配，**不需要改 JS 内核**。
- **三种注入方式**：A 构建时写进 `index.html`；B 运行时 `onPageFinished` 注入（**当前采用 B**）；C 先设 `window.MTX_MOBILE_CONFIG` 再注入覆盖默认。详见 `renderer-overrides/README.md`。
- **运行期 API**：`window.__MTX_MOBILE_ADAPT__.enable()/disable()/setTheme('dark'|'light')`。

> ⚠️ Motrix 用 React+Tailwind，class 名可能随版本变。适配层刻意只依赖标准元素/ARIA/Tailwind 通用类 + `data-mtx-*` 钩子；结构不符时在 CSS 末尾追加覆盖或补钩子即可，不改 JS 内核。

## 5. 改包名 / 图标 / 应用名 / 签名 / 上架

### 5.1 应用名
改 `android/app/src/main/res/values/strings.xml` 里的 `app_name`。

### 5.2 包名（applicationId）
- 主改 `android/app/build.gradle.kts:13` 的 `applicationId`（如 `app.motrix.android` → `com.yourco.motrix`）。
- `namespace`（`:9`）建议与代码包名 `app.motrix.android` 保持一致先不动；只改 `applicationId` 即可发布成不同包名的 App。
- `AndroidManifest.xml` 里 FileProvider 的 `android:authorities="${applicationId}.fileprovider"` 会自动跟随，无需手改。
- 若要**连代码包名一起改**：需同时改 `namespace` + 移动 `java/app/motrix/android/*.kt` 目录并改 `package` 声明（较繁琐，非必要不动）。

### 5.3 图标
- 当前是矢量的 `res/drawable/ic_launcher.xml`（被 Manifest 的 `android:icon`/`roundIcon` 引用）。
- 换图标：用 Android Studio 的 **Image Asset** 生成 mipmap，或在 `res/` 放 `mipmap-*/ic_launcher.png` 并把 Manifest 改指 `@mipmap/ic_launcher`。

### 5.4 版本号
`android/app/build.gradle.kts:16-17`：`versionCode`（每次上架 +1）、`versionName`（如 `"2.4.3-android.1"`）。

### 5.5 签名（release）
```powershell
# 1) 生成 keystore（一次性，妥善保管）
keytool -genkeypair -v -keystore motrix-release.jks -alias motrix ^
  -keyalg RSA -keysize 2048 -validity 10000
# 2) 在 android/app/build.gradle.kts 增加 signingConfigs 并让 release 使用它（或本地 gradle.properties 注入口令）
# 3) 出包
gradle assembleRemoteRelease
```
> 口令与 keystore 放本机、勿入库。`release` 已开 `isMinifyEnabled=true`（`app/build.gradle.kts:37`），混淆规则在 `proguard-rules.pro`——若桥/反射类被裁，需在此加 `-keep`（见 §7 坑9）。

### 5.6 上架要点
- 产物用 `bundleRelease`（出 `.aab`）；`targetSdk=35`、`minSdk=24` 已满足主流商店要求。
- 商店需**隐私政策**与**权限用途说明**：本 App 只用 `INTERNET / ACCESS_NETWORK_STATE / FOREGROUND_SERVICE(+DATA_SYNC) / POST_NOTIFICATIONS / WAKE_LOCK`，存储走 SAF（见 Manifest）。
- **合规**：内嵌 aria2（GPLv2）须随包提供"源码获取方式"（见 `third_party/aria2/NOTICE.md`）；改名/换标注意上游 **Motrix 商标与版权**，保留其 LICENSE 署名。

## 6. 升级到 Motrix 新版本

> 目标：换上游版本时，只重做"stage 前端/后端 + 适配层回归"，原生壳通常不用大改。

1. **取新源码**：放到新目录，如 `C:\工作日志\projects\src-motrix\Motrix-vX.Y.Z`。
2. **重新 stage 前端与后端**（一条命令，别手搬）：
   ```powershell
   pwsh -File .\scripts\build-renderer.ps1 -RepoRoot C:\工作日志\projects\src-motrix\Motrix-vX.Y.Z
   ```
   它做：`pnpm install` → `pnpm build:server` → 把 `dist/renderer-web` 覆盖进 `assets/renderer-web/`，`dist/server` 覆盖进 `assets/nodejs-project/dist-server/`（只替换这两个子目录，不动 `main.js`）。
3. **核对 server 契约有无变化**（关键，决定要不要改 `main.js`）：
   - 后端入口是否仍是 `dist/server/index.mjs`；
   - 监听用的环境变量是否仍为 `PORT`？aria2 路径是否仍读 `MOTRIX_ARIA2_BIN`？数据根是否仍 `MOTRIX_DATA_DIR`？—— 对照 `docs/02 §2.4` 的环境变量表与 `§5` 的 C1–C7 逐条重核。
   - 认证是否仍是 operator token 登录（`POST /rpc/auth/login` → `mtx_op` cookie）。
4. **前端静态资源 base**：确认为相对 `./`，否则 WebView 在 `http://127.0.0.1:PORT/` 下会 404。
5. **适配层回归**：新版 DOM/class 若变，按 `renderer-overrides/README.md` 的钩子调整 `mobile-adapt.css`，并覆盖到 `assets/`。
6. **重建 + 真机回归**：`gradle assembleRemoteDebug` → 装真机 → 按 `docs/06-QA测试计划.md` 跑核心 7 流程。
7. **同步版本号**：`build.gradle.kts` 的 `versionName` 建议带上游版本（如 `"2.4.4-android.1"`）。

## 7. 常见二次开发坑（真金白银）

> 前 5 条是"回环契约"类，最容易被忽略导致**模式 B 起了后端却连不上/白屏/停在解锁屏**。

1. **环境变量名对不上**：脚手架 `main.js` 用 `MOTRIX_PORT` / `MOTRIX_ARIA2_PATH`，但上游 server 实际读 `PORT` / `MOTRIX_ARIA2_BIN`（见 `docs/02 §2.4、§5 C1/C2`）。端内必须让 `main.js` 写 `process.env.PORT` 和 `MOTRIX_ARIA2_BIN`，否则 server 不监听或找不到 aria2。⚠️ 当前 `main.js` 尚未完全对齐，属待修正项。
2. **握手文件路径不一致**：`main.js` 写 `<MOTRIX_DATA_DIR>/motrix-ready.json`，而 `MainActivity.pollReadyFile()` 轮询 `filesDir/motrix-ready.json`（`MainActivity.kt:166`）。务必令 `MOTRIX_DATA_DIR == filesDir`（`docs/02 §5 C4`），否则轮询永远超时→回 setup。
3. **环境变量注入方式**：`NodeJS.startNodeWithArguments` **不注入自定义 env**（`docs/02 §5 C3`）。运行参数要走 **argv 或旁路 `bootstrap.json`** 传给 `main.js`，别指望 `process.env` 自动有值。
4. **认证网关默认拒绝**：`/rpc/*`、`/rpc/events` 需 operator token 登录后才可用。当前 `MainActivity` 尚**未**在 `onPageFinished` 注入自动登录脚本（`docs/02 §5 C5、§2.3`）→ 模式 B 可能停在 `OperatorUnlockGate` 解锁屏。修法：读 `<DATA_DIR>/operator-token`，注入 `fetch('/rpc/auth/login',{...body:JSON.stringify({token})})` 后 `location.reload()`。
5. **不要改用 `file://` 加载界面**：必须用 `loadUrl("http://127.0.0.1:<真实port>/")` 同源加载，否则同源 Cookie、WebSocket、登录全部失效（renderer 只认同源，`docs/02 §0`）。真实端口以握手文件为准，勿写死。
6. **better-sqlite3 的 ABI 坑**：用 PC 上 Node 编出来的 `.node` 在端内会报 `NODE_MODULE_VERSION`/`invalid ELF`。要正解就用**内置 Node 的确切版本**走 NDK 交叉编译；先跑通可设 `MOTRIX_SQLITE_DRIVER=memory` 降级（牺牲持久化），或用 remote 模式（`docs/04 R1`）。
7. **aria2 二进制命名与权限**：必须落到 `jniLibs/<abi>/libaria2c.so`（**只有 `lib*.so` 才会随 APK 解压到 `nativeLibraryDir`**），且启动时 `chmod 0755`；路径经 `MOTRIX_ARIA2_BIN` 传给 server。
8. **明文流量限制**：`res/xml/network_security_config.xml` 只对 `127.0.0.1`/`localhost` 放行明文；连远程 **http** 服务器时需另加域名白名单，否则 WebView 拒绝加载。
9. **release 混淆裁类**：`release` 开启 minify，`MotrixJsBridge`（被 JS 反射调用）、`com.janeasystems.nodejsmobile.NodeJS`（反射）等要加 `-keep` 到 `proguard-rules.pro`，否则 release 包运行期 `ClassNotFound`。
10. **embedded 变体没放 aar**：`MotrixServerService.startNodeBridge()` 反射找不到 `NodeJS` 会**安全降级为日志告警、不崩溃**（`MotrixServerService.kt:57-59`）。要真正启用端内，必须放 `app/libs/nodejs-mobile.aar` 并取消 `build.gradle.kts:70` 的注释。
11. **Node 版本差异**：上游用较新 Node 构建，nodejs-mobile 内置 Node 可能更低（`package.json engines: >=16`）。用到的新内置 API 可能 `undefined`，需 polyfill；原生模块必须匹配内置 ABI（`docs/04 R3`）。
12. **SAF 目录与 aria2 写入**：`pickDownloadDir()` 拿到的是 SAF `treeUri`，aria2 **不能直接写 SAF URI**。需"中转目录写入 + 完成后搬移"或受管存储方案（`docs/04 R8`），尚未打通前下载目录建议用应用可写路径。

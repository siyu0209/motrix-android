# 10 · 布局断点分析（应用外壳 App Shell）

> 归属：程序逆向分析 + 程序审计（reverse-auditor）
> 任务（来自 Lead）：只读分析 Motrix 原版 React Web 渲染器的「侧边栏 + 顶栏（window-chrome / 应用壳）」布局，产出结构事实，并给出 3B 下彻底避免「页面标题与 m·o 徽标重叠」的最稳做法。
> 源码基线：`projects/src-motrix/Motrix-main`（Motrix Turbo v2.4.3）。**只读分析，未改任何代码。**
> 标注：✅=源码直证；🟡=按源码宽度/样式相加的推断；❌=源码明确不支持。

## 0. 结论先行（TL;DR）

1. **顶栏（WindowChrome）在 Web/安卓渲染器里是 `position:fixed` 的透明覆盖条，高 40px，`z-index:30`，横跨全宽**。它不占布局高度 —— 所以内容必须自己让出这 40px，否则会被它盖住。
   - ✅ `src/renderer/components/window-chrome/window-chrome.tsx:226-233`（fixed/top0/left0/right0/zIndex30/transparent）；`:199-202`（height）；✅ `src/shared/constants/window-chrome.ts:2`（`DESKTOP_WINDOW_CHROME_HEIGHT = 40`，web 目标恒取 40）。
2. **侧栏折叠断点 = 768px（Tailwind `md` = 48rem）**。`<768` 时侧栏不再是「停靠列」，而变成**覆盖式抽屉（Sheet，portaled）**；`≥768` 才停靠并占宽。
   - ✅ `src/renderer/hooks/use-mobile.ts:3`（`MOBILE_BREAKPOINT = 768`）；✅ `src/renderer/components/ui/sidebar.tsx:203-228`（isMobile → Sheet）；`:230-276`（desktop `hidden md:block` / `md:flex`）；✅ `src/renderer/styles/globals.css:29`（`@media (width < 48rem)`）、`:307`（`(width >= 48rem)`）。
3. **内容区顶部避让不是「无脑 padding-top=40px」，而是「内建 header 占位 + 两轴分级」**：
   - 竖轴：满血态 `PanelShell` header 自带 `pt-8`(32px) + 内容卡 `m-2`(8px) = **40px**，标题恰好落在 40px 顶栏下沿（✅ `panel-shell.tsx:48` + `sidebar.tsx:340`；comment `panel-shell.tsx:46-47`「32px above the title… header remains 80px tall」）。
   - 横轴：紧凑态（`compact-header`）靠 `padding-inline-start: var(--window-chrome-safe-area-leading)` = **160px** 把标题推到 m·o 徽标右侧（✅ `panel-shell.tsx:55`；✅ `globals.css:727-730`）。
   - `<640px`：CSS 强制 `padding-block-start:44px`（触屏 56px）+ `padding-inline:16px`，改为「标题下移到顶栏之下」（✅ `globals.css:732-759`）。
4. **3B 里「页面标题与 m·o 徽标重叠」的唯一根因：自绘标题没有吃到上述两轴避让**（既没走 `PanelShell`/`data-slot="panel-shell-header"`，也就拿不到 `ps-160`/`pt-44`）。**最稳做法 = 让标题走内建的 `PanelShell`（或至少打上 `data-slot="panel-shell-header"`），不要自绘头**。若必须自绘，见 §6 的显式选择器配方。
5. m·o 徽标的实占区：菜单触发器宽 **72px**、高 28px，起点 x=12px（顶栏内边距），即 **x≈12..84**；连同右侧「折叠侧栏」按钮(28)+「新建任务」按钮(28)+间距，左侧控件簇约 **152px**，故官方安全区取整 **160px**（🟡 依据 `web-menu-button.tsx:345`、`sidebar-trigger-button.tsx:23`、`add-task-trigger-button.tsx:29` 宽度相加 + `globals.css:728` 的 160）。

## 2. 顶栏 WindowChrome：高度 / 定位 / 层级

### 2.1 高度 = 40px（web）
✅ `window-chrome.tsx:199-202`：
```ts
const height = windowChromeHeight(
  __MOTRIX_TARGET__ === 'electron' ? platform : 'web',
  compact || isOverlay
)
```
✅ `window-chrome.ts:9-13`：`windowChromeHeight(platform, compact)` 当 `platform==='linux' || (darwin && !compact)` 返回 54，否则 40。web 目标传 `'web'` → **恒 40**。

### 2.2 定位 = fixed 透明覆盖
✅ `window-chrome.tsx:226-233`：
```ts
...(isOverlay && {
  position: 'fixed', top: 0, left: 0, right: 0,
  zIndex: 30, background: 'transparent',
})
```
- 结论：40px 高的覆盖条**浮在所有内容之上**（但自身透明），不参与文档流高度。**这是「内容必须自避让」的根源**。
- 层级：顶栏 z=30；面板操作按钮用 `z-40`（✅ `panel-shell.tsx:66-74` 注释「above the z-30 WindowChrome drag strip but below the z-50 modal」）；弹层 z-50。

### 2.3 内边距与徽标占位（web）
✅ `window-chrome.tsx:212-223`：非 mac 交通灯、非 WCO 时 `paddingInlineStart = 12`、`paddingInlineEnd = 20`（web 无桌面窗控 → 20）。
- leading 槽 = `<MotrixMenuButton/>`，`me-1.5`(6px)（✅ `:266-276`，`insetCaptionRow` 时加 `pt-3.5`=14px 垂直居中）。
- 触发器宽度：`w-[72px] h-7`（✅ `web-menu-button.tsx:345`）；LOGO `h-2.5 w-11`（44×10）+ chevron `size-3`（✅ `motrix-logo.tsx:6-21`）。
- ⇒ 徽标点击区 x≈**12..84**，y≈13..41（40px 条内 28px 行居中 + `pt-3.5`）。
- ⇒ 左侧控件簇总宽 ≈ 12 + 72(logo) + 6(gap) + 28(侧栏钮) + 6(gap) + 28(新建钮) ≈ **152px** → 官方安全区 `--window-chrome-safe-area-leading: 160px`（🟡 推断，源 `globals.css:728`）。

## 3. 侧边栏与断点

### 3.1 断点 = 768px
- ✅ `hooks/use-mobile.ts:3` `MOBILE_BREAKPOINT = 768`；`useIsMobile()` 用 `matchMedia('(max-width: 767px)')`（同文件）。
- Tailwind `md = 48rem = 768px`：✅ `globals.css:29` `@media (width < 48rem)`、`:307` `@media (width >= 48rem)`。

### 3.2 <768 = 覆盖抽屉（Sheet），不是停靠列
✅ `sidebar.tsx:203-228`：`if (isMobile)` → 渲染 `Sheet`（`SheetContent data-mobile="true"`，宽 `--sidebar-width` = **18rem(288px)**，`max-w-[calc(100vw-2rem)]`）。
✅ `sidebar.tsx:230-276`：`else`（≥768）→ 外层 `group peer hidden md:block`，内层 `sidebar-container` 为 `fixed inset-y-0 z-10 hidden md:flex w-(--sidebar-width)`。

### 3.3 侧栏宽度
✅ `sidebar.tsx:27-29`：`SIDEBAR_WIDTH='12.5rem'(200px)`、`SIDEBAR_WIDTH_MOBILE='18rem'(288px)`、`SIDEBAR_WIDTH_ICON='3rem'(48px)`。

### 3.4 Provider 会在 <768 强制报「collapsed」
✅ `sidebar.tsx:145-170`，尤其 `:153`：
```tsx
data-state={isMobile ? 'collapsed' : state}
```
注释（`:149-152`）：「Below md the docked sidebar cannot be visible (it renders as a Sheet), so report collapsed regardless of the desktop open flag.」
⇒ **<768 时，无论用户桌面端侧栏是开是关，`data-state` 都是 `collapsed`**，这直接驱动紧凑态（见 §4）。

## 4. 内容区避让机制（两轴 + 三级）

### 4.1 紧凑态（compact-header）触发条件
✅ `globals.css:28-35`：
```css
@custom-variant compact-header {
  @media (width < 48rem) { @slot; }                       /* <768 */
  &:where(.group\/sidebar-wrapper[data-state="collapsed"] *) { @slot; }  /* 侧栏收起 */
}
```
✅ JS 对等：`use-compact-header.ts:12-16` `return ctx.isMobile || ctx.state === 'collapsed'`（注释 `:4-10`「Mirrors the CSS compact-header: variant — keep both in sync」）。
⇒ **紧凑态 = 「viewport<768」或「侧栏收起」二者之一**。

### 4.2 内容卡 `SidebarInset` 的外边距
✅ `sidebar.tsx:334-347`：
```tsx
'max-md:m-2',
'md:peer-data-[variant=inset]:m-2 md:peer-data-[variant=inset]:ms-0 md:peer-data-[variant=inset]:rounded-xl md:peer-data-[variant=inset]:shadow-sm md:peer-data-[variant=inset]:peer-data-[state=collapsed]:ms-2'
```
`m-2 = 0.5rem = 8px`。⇒ 内容卡四边内缩 8px（作为白色卡片与侧栏渐变背景的分隔）。

### 4.3 PanelShell header 的两套 padding
✅ `panel-shell.tsx:43-57`：
```tsx
<header data-slot="panel-shell-header" className={cn(
  'flex shrink-0 items-center justify-between gap-4 px-6 pt-8 pb-3 transition-[padding] ...', // 满血态：左右24 / 上32 / 下12
  'compact-header:py-[5px]',
  'compact-header:ps-[var(--window-chrome-safe-area-leading)] compact-header:pe-[var(--window-chrome-safe-area-trailing)]',
  headerClassName)}>
```
- 满血态：`px-6 pt-8 pb-3` → 标题顶在「inset 8 + pt 32 = **y=40**」，正好越过 40px 顶栏（✅ 注释 `:46-47`「Standard headers keep 32px above the title and 12px below it… header remains 80px tall」）。
- 紧凑态：`py-[5px]` + `ps-160 / pe-24`，标题行 28px 居中对齐到「顶栏图标线 y=27」（✅ 注释 `:49-54` 给出公式 `8 + 5 + 14 = 27`，与交通灯 `{x:20,y:20}` 同线）。

### 4.4 `<640px` 的覆盖规则（关键！）
✅ `globals.css:732-747`：
```css
@media (width < 640px) {
  .web-window-chrome [data-slot="panel-shell-header"],
  .electron-window-chrome [data-slot="panel-shell-header"] {
    padding-block-start: 44px;   /* 标题下移到顶栏之下 */
    padding-inline: 16px;        /* 左右改回 16（覆盖紧凑态的 ps-160） */
    flex-wrap: wrap; gap: 8px;
  }
}
```
✅ `globals.css:748-759`：`@media (pointer: coarse) and (width < 640px)` 再抬到 `padding-block-start:56px`（触屏更宽裕）。

### 4.5 把三档串起来（这是全篇最该记住的结论）

| 宽度 | 侧栏形态 | 紧凑态? | header 竖轴 | header 横轴 | 标题与 m·o 是否重叠 |
|---|---|---|---|---|---|
| **≥768，侧栏展开** | 停靠列（占 200px） | 否 | `pt-8` → 标题 y=40（顶栏下） | `px-6`（x=24，但已下移） | 否（竖向已分离） |
| **≥768，侧栏收起** | 停靠列（缩为 0/图标） | 是 | `py-5` → 标题在 y≈27 行 | `ps-160`（x=160） | 否（横向让开 160） |
| **640–767** | Sheet 抽屉 | 是 | 同上 y≈27 行 | `ps-160` | 否（横向让开 160） |
| **<640** | Sheet 抽屉 | 是 | `<640` 规则 → `pt-44`（触屏 56） | `<640` 规则 → `px-16` | 否（竖向已推到顶栏下，x=16 也不撞） |

> 换句话说：**内置逻辑用「要么横向让 160px、要么纵向下移 40/44/56px」两条互斥的兜底，保证任何宽度标题都不会压到 m·o 徽标**。一旦自绘标题脱离 `PanelShell`/`data-slot="panel-shell-header"`，这两条兜底全部失效 → 就重叠了。

## 5. 「侧栏收起（<768）」时内容顶部的正确避让方式

**结论：是「内建 header 占位」，不是「自己给内容加 padding-top=40px」。** 具体：

1. **只要你用了 `PanelShell`（页面标题走它的 `title`）**：
   - 640–768：标题与徽标**同处 y≈27 一行**，靠 `ps-[--window-chrome-safe-area-leading]`(160px) 横向让开，**竖向并不让出 40px**（顶栏透明，允许内容在其下方）。
   - <640：`<640` 规则把 `padding-block-start` 抬到 44px（触屏 56px）并把左右内边距改回 16px，标题**下移到顶栏之下**，此时靠竖向分离。
   - ⇒ 你**不需要**再额外加 `padding-top`。
2. **如果你自绘头部、没用 PanelShell**：**必须自己补两轴避让**（否则就是 3B 的重叠 bug）：
   - 竖向：给内容首个块 `padding-top ≥ 40px`（配 `m-2` 则 32px 即可，因为 inset 已有 8px）；窄屏（<640）建议 ≥44px（触屏 56px）。
   - 横向：任何落在 y<40 顶栏带内、靠左的内容，`padding-inline-start ≥ 160px`（即 `var(--window-chrome-safe-area-leading)`），否则会被 m·o 徽标 + 侧栏钮 + 新建钮（≈左 152px）盖住且**点击被 z-30 顶栏拦截**。

## 6. 3B「彻底避免页面标题与 m·o 徽标重叠」的最稳做法

### 6.1 首选（零魔法数字）：复用内建 header 契约
- **把页面标题放进 `PanelShell`**（`components/desktop-kit/panel/panel-shell.tsx`），或至少给自绘头容器加属性 **`data-slot="panel-shell-header"`** 并确保它处在 `.web-window-chrome` 作用域内（web 渲染根已带 `web-window-chrome`，✅ `app-layout.tsx:102`）。
  - 这样 `globals.css` 的 `compact-header` 变体（`ps-160`）与 `<640` 覆盖（`pt-44/56`）自动生效，**横竖两轴按宽度自动切换兜底**，无需任何像素硬编码。
- 断点必须与官方**完全对齐**：`768px`（`48rem`，侧栏折叠）、`640px`（header 下移/换行）、`pointer:coarse & <640`（`56px`）。**不要自造 600/720 之类断点**，否则会落进官方规则的空档。

### 6.2 兜底（不能改 DOM 时）：显式选择器配方（照抄即可）
```css
/* —— 3B：应用壳顶栏固定 40px，内容区整体避让 —— */

/* ① 竖轴：让页面主标题落到 40px 固定顶栏之下。
      PanelShell 已内建 pt-8(32px)+inset m-2(8px)=40；自绘头则显式补足。 */
.web-window-chrome [data-slot="sidebar-inset"] > .your-page-root {
  padding-block-start: 40px;            /* 无 PanelShell 时用；有 PanelShell 可省略 */
}
@media (width < 640px) {
  .web-window-chrome [data-slot="sidebar-inset"] > .your-page-root {
    padding-block-start: 44px;          /* 与官方 <640 对齐 */
  }
}
@media (pointer: coarse) and (width < 640px) {
  .web-window-chrome [data-slot="sidebar-inset"] > .your-page-root {
    padding-block-start: 56px;
  }
}

/* ② 横轴：任何与顶栏同一行（y<40）且左对齐的标题/工具条，左内边距 ≥160px，
      避开 m·o 徽标(x12..84)+侧栏钮+新建钮(≈左152px)。 */
.web-window-chrome .your-page-title-row {
  padding-inline-start: var(--window-chrome-safe-area-leading); /* web=160px */
}
/* 若不希望标题与徽标同行，也可直接在 >=768 把标题强制下移： */
@media (width >= 48rem) {
  .web-window-chrome .your-page-title-row { padding-block-start: 40px; padding-inline-start: 24px; }
}
```

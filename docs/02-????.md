## 0. 结论先行

1. **架构本质**：Motrix = 「Web 渲染层 ↔ HTTP JSON-RPC + WS ↔ Fastify 服务端 + core（aria2/ffmpeg 子进程）」。渲染层只认同源（`docs/01 §3.3`），服务端可独立运行。→ 安卓 App = **WebView 壳 + （模式B 时）本机 Node 后端 + 安卓 aria2c**。
2. **双模共存、同一壳**：`app/build.gradle.kts:22-33` 已定义 `remote` / `embedded` 两个 flavor（`EMBEDDED_SUPPORTED` 布尔开关）。两模式**共用同一 WebView + 同一份 `dist/renderer-web`**，差异仅在「后端指向远程 URL 还是本机 127.0.0.1」。这由 `MainActivity` 的三分支启动逻辑承接（`MainActivity.kt:61-66`）。
3. **推进顺序（风险最低）**：**先模式 A 打通（不依赖任何原生模块，最快验证 renderer↔server 契约）→ 再攻模式 B 的三大硬骨头（better-sqlite3 / Node 版本 / aria2c）**。模式 A 同时是模式 B 跑不通时的兜底交付。
4. **必须补的两块「隐形地基」**（现状脚手架缺）：
   - **认证登录注入**：控制面默认拒绝，WebView 必须用 operator token 登录（`docs/01 §8 P0-3`、`§3.4`）。
   - **引导契约修正**：`main.js` 的端口/aria2 路径变量名、env 注入、ready 文件路径与 server 不一致（`docs/01 §8.1`、`P1-1`）。

## 2. 模式 B：端内内嵌（详细方案）

### 2.1 进程模型
| 角色 | 载体 | 职责 |
|---|---|---|
| UI 壳 | `MainActivity`（WebView） | 加载本地 UI、注入适配、JS 桥、返回键、magnet intent |
| 后台宿主 | `MotrixServerService`（前台服务） | 保活、通知；反射启动 nodejs-mobile（`MotrixServerService.kt:49-60`） |
| Node 运行时 | nodejs-mobile（NodeJS aar） | 跑 `main.js` → 动态 import `dist-server/index.mjs` |
| 后端 | Fastify（dist/server） | 控制面 + 静态托管 + 引擎监管 |
| 引擎 | aria2c 子进程 | 真正下载 |
| 媒体（可选） | ffmpeg 子进程 | 非核心，先不打包 |

### 2.2 启动时序（目标态，含对现有脚手架的修正点）
1. 用户选「端内模式」→ `startForegroundService(MotrixServerService)`（`MainActivity.kt:156-163`）。
2. Service 解压 `assets/nodejs-project/**` → `filesDir/nodejs-project`，反射 `NodeJS.startNodeWithArguments(["node", main.js])`（`MotrixServerService.kt:51-55`）。
   - **修正**：该 API 不注入自定义 env。需把运行参数（DATA_DIR、端口、aria2 路径）经 **argv 或旁路 `bootstrap.json`** 传给 `main.js`，而非依赖 `process.env`。
3. `main.js`：解析 `DATA_DIR`（应为 `filesDir`，与 `MainActivity.kt:166` 轮询路径统一）→ `process.chdir(DATA_DIR)` → 垫 `TMPDIR/HOME/XDG_*` → 探测空闲端口 → **写回 `process.env.PORT`**（修正 P0-4a）→ 设 `MOTRIX_ARIA2_BIN`（修正 P0-4b）→ `import(dist-server/index.mjs)`。
4. server：`createApp(...)` → 读 `MOTRIX_OPERATOR_TOKEN` 或写 `<DATA_DIR>/operator-token`（`operator-token.ts:36-61`）→ `app.listen({port: PORT, host:'0.0.0.0'})`（`index.ts:2053-2064`）→ `startServerEngine(supervisor, MOTRIX_ARIA2_BIN)`（`index.ts:1889-1891`）→ aria2 就绪。
5. `main.js` 写 `<DATA_DIR>/motrix-ready.json` + 打印 `[MOTRIX_READY] {json}`（`main.js:256-276`）。
6. `MainActivity.pollReadyFile` 轮询该文件 → 取 `port` → `loadUrl("http://127.0.0.1:$port")`（`MainActivity.kt:165-178`）。
   - **修正**：文件路径必须与步骤 3 的 `DATA_DIR` 一致。
7. `onPageFinished`：注入 `mobile-adapt.css/js`（`MainActivity.kt:180-191`）+ **operator 自动登录**（见 2.3）→ 进入 UI。

### 2.3 认证方案（模式 B 自动登录，关键补充）
- 事实：`/rpc/*`、`/api/*`、`/rpc/events` 默认拒绝；仅静态 GET + `login/status/healthz` 放行（`operator-auth.ts:170-188`）。渲染层有解锁屏 `OperatorUnlockGate`，登录 API `POST /rpc/auth/login {token}` → 下发 `mtx_op` cookie（`operator-auth.ts:324-347`；`operator-auth.ts`（renderer）:137-162）。
- **推荐流程（B）**：server 启动后已把 token 写入 `<DATA_DIR>/operator-token`（0600，同 app uid 可读）。`MainActivity` 在 `onPageFinished` 读取该文件，注入：
  ```js
  fetch('/rpc/auth/login',{method:'POST',headers:{'content-type':'application/json'},
    credentials:'same-origin',body:JSON.stringify({token:'<读取到的token>'})})
    .then(r=>r.ok && location.reload())
  ```
  → cookie 落地（同源 127.0.0.1:PORT，SameSite=Strict 生效）→ 刷新后进入已登录 UI；WS 事件同源，通过 `exactBrowserOrigin` 校验（`operator-auth.ts:309-320`）。
- 备选：原生生成设备口令并设 `MOTRIX_OPERATOR_TOKEN`（若 env 注入打通），再注入同一 token。二者产出一致，优先前者（不依赖 env 注入）。
- 安全：token 存 `Prefs`（`EncryptedSharedPreferences`，`Prefs.kt:13-24`）避免明文落盘；明文通道仅限回环（`network_security_config.xml:3-7`）。

### 2.4 环境变量正确契约（修正后，务必以此为准）
| 变量 | 作用 | server 读取处 | 模式 B 建议值 |
|---|---|---|---|
| `PORT` | 监听端口 | `src/server/index.ts:2053` | `main.js` 探测后写回（16800 起），**不要用 `MOTRIX_PORT`** |
| `MOTRIX_DATA_DIR` | 数据根 | `src/server/platform/services.ts:65-66` | `filesDir`（与 ready 文件、token 同目录） |
| `MOTRIX_ARIA2_BIN` | aria2 可执行路径 | `services.ts:69-70` | `nativeLibraryDir/libaria2c.so` 绝对路径 |
| `MOTRIX_RENDERER_DIR` | 前端静态目录 | `src/server/index.ts:321-323` | 缺省 `../renderer-web`（按 stage 结构即可，无需设） |
| `MOTRIX_WEB_BASE_PATH` | 子路径基址 | `src/server/index.ts:1546` | 一般留空 |
| `MOTRIX_OPERATOR_TOKEN` | 控制面口令（可选） | `operator-token.ts:41` | 不设则用文件 token（推荐） |
| `MOTRIX_FFMPEG_PATH` | ffmpeg（可选） | `ffmpeg-detect-server.ts` | 留空（先不打包） |
| `MOTRIX_PUBLIC_URL` | WS origin 期望值 | `src/server/index.ts:1569` | 模式 B 可不设（Host 头即 127.0.0.1:PORT） |
| `NODE_ENV` | 运行模式 | 多处 | `production` |

### 2.5 aria2 集成
- 二进制：`fetch-aria2-android.ps1` 落 `third_party/aria2/<abi>/aria2c` → stage 成 `jniLibs/<abi>/libaria2c.so`（改名 `lib*.so` 才会解压进 `nativeLibraryDir`）。
- 启动前 `chmod 0755`；`MOTRIX_ARIA2_BIN` 指其绝对路径；`Aria2ConfigBuilder` 自动加 `--enable-rpc --rpc-secret --enable-sqlite3-persistence --save-session`（`aria2-config-builder.ts:214-251`，`--enable-sqlite3-persistence` 为 motrix aria2 fork 特性，官方 aria2 无 → 若用官方二进制，`hasSqlitePersistence=false` 时自动退回文本 `aria2.session`，见 `engine-supervisor.ts:474-540`）。
- DHT/tracker：BT 依赖网络与 tracker，`⚠️待真机`验证连通性。

### 2.6 数据目录布局（`DATA_DIR` 下）
`settings.json`（App/引擎设置）、`motrix.db`(+`-wal`/`-shm`，better-sqlite3)、`aria2.session`、`operator-token`、`torrents/`、`plugins/`（含 builtin）、`tmp/`、`logs/`、`motrix-ready.json`（握手）。见 `src/server/index.ts:1626-1636` 的 storage 诊断字段。

## 3. 模式 A：远程薄客户端（详细方案）

### 3.1 流程
1. 用户在设置页输入 `REMOTE_URL`（含 scheme，缺省补 `http://`，尾部去 `/`，`MainActivity.kt:127-136`）+ **operator token**。
2. `Prefs` 加密存 `server_base` 与 token（`Prefs.kt`）。
3. `loadUrl(REMOTE_URL)` → 页面即远端 server 托管的官方 UI（同源）。
4. `onPageFinished` 注入登录（同 §2.3 的 fetch 方式，token 来自用户输入）→ cookie 建立 → 进入 UI。
5. 本机**不跑** Node / aria2，无原生模块依赖。

### 3.2 注意事项
- 服务端若在反向代理/域名后，必须设 `MOTRIX_PUBLIC_URL` 且与手机访问 origin 完全一致，否则 `/rpc/events` WS 因 origin 不匹配被 403（`operator-auth.ts:115-141,309-320`）。
- 远程为 HTTPS 时，WebView 明文策略不受影响；`network_security_config.xml` 仅对 127.0.0.1/localhost 放行明文。
- 远程 token 由用户在服务器 `<dataDir>/operator-token` 或 `MOTRIX_OPERATOR_TOKEN` 取得（`operator-token.ts` 注释与实现）。

## 4. 双模切换与降级判定

| 触发 | 行为 |
|---|---|
| 首次启动，无保存配置 | 显示 setup 面板，让用户「连接远程」或「端内运行」（`MainActivity.kt:61-66,143-146`） |
| 端内启动失败（原生模块/Node/aria2 异常） | `main.js` 写 `{ready:false,error}` 握手 + `[MOTRIX_FAILED]`（`main.js:417-427`）；`MainActivity` 轮询超时（>30 次）→ 提示「改用远程服务器模式」并回 setup（`MainActivity.kt:176`） |
| remote flavor | `EMBEDDED_SUPPORTED=false`，「端内」按钮提示需用 embedded 变体（`MainActivity.kt:137-140`） |
| 运行期 server 崩溃 | 前台服务 `START_STICKY` 尝试重拉；WebView `onReceivedError` 主框架失败 → 回 setup（`MainActivity.kt:108-116`） |

**原则**：模式 A 永远是兜底可用路径（零原生依赖）；模式 B 是保真目标，跑不通时**不让用户拿到白屏/半死状态**，明确引导切换。

## 6. 原生侧需新增/改造的能力（只列方案，不写实现）

1. **Android PlatformServices 适配**：`src/shared/platform/services.ts` 定义 `PlatformServices`（含 `host: RunHost`、`userDataDir/extraResourceDir/aria2BinaryPath/isDev`）。可新增 Android 宿主实现替换 Node 默认（`createNodePlatformServices` 为参照，`services.ts:55-80`），把 `userDataDir=filesDir`、`aria2BinaryPath=nativeLibraryDir/libaria2c.so` 注入，避免依赖环境变量。

## 8. 构建与产物装配架构

```
Motrix 源仓库                          motrix-android 产物
─────────────                          ────────────────────
pnpm build:server ─┬─ dist/server/ ───► android/app/src/main/assets/nodejs-project/dist-server/   (后端)
                   └─ dist/renderer-web/ ► android/app/src/main/assets/renderer-web/              (前端静态站)
fetch-aria2-android ─ third_party/aria2/<abi>/aria2c ─► android/app/src/main/jniLibs/<abi>/libaria2c.so
nodejs-mobile.aar ─── (embedded 变体) ─► android/app/libs/nodejs-mobile.aar（build.gradle 里取消注释引用）
gradle assembleDebug / assembleEmbeddedDebug ─► app-debug.apk / app-embedded-debug.apk
```
- 脚本链：`scripts/build-renderer.ps1`（pnpm 构建 + stage）→ `fetch-aria2-android.ps1` → `build-all.ps1`（+ stage jniLibs + gradle）。详见 `docs/03-构建指南.md`。
- `app/build.gradle.kts`：`packaging.jniLibs.useLegacyPackaging = true`（保证 `libaria2c.so` 可解压执行）。
- 双 flavor 产物：`remote`（不含 Node/aria2，体积小、零原生风险）、`embedded`（全内嵌）。

## 9. 性能 / 安全 / 兼容 设计要点

- **性能**：WebView 大列表虚拟化/分页（R6）；`MotrixServerService` 解压 assets 加版本判定避免每次全量拷贝（01 P2-5）；按 ABI split 减小包体（R10）。
- **安全**：JS 桥最小暴露（P2-3）；operator token 存 `EncryptedSharedPreferences`；明文流量仅回环（`network_security_config.xml`）；服务端绑定 `0.0.0.0` 但手机场景实际仅本机可达（`index.ts:2053`），如需收紧可后续加「仅 127.0.0.1」平台适配。
- **兼容**：nodejs-mobile Node 版本核对 + polyfill（R3）；aria2 官方/fork 二进制差异自动降级文本 session（`engine-supervisor.ts:474-540`）；SAF 用中转目录规避权限（R8）。

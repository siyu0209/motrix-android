### 术语

- **模式B（内嵌）**：nodejs-mobile 在 App 内起 `dist/server`，aria2c 安卓二进制作引擎，全部跑 `127.0.0.1:<PORT>`。
- **模式A（远程）**：WebView 连 PC/NAS 上的 Motrix server（填 URL + bridge 令牌），手机作遥控客户端。
- **原生 bug**：Motrix 上游本身存在、移植前就有的缺陷。
- **改造引入 bug**：因安卓移植（WebView 壳/桥/nodejs-mobile/aria2 交叉编译/renderer-overrides）新引入的缺陷——**必须 100% 修复**。

## 1. 测试策略总览

### 1.1 测试层级

1. **静态完整性校验**（自动化）：`tests/validate-deliverable.ps1` 校验交付树文件齐全 —— 冒烟闸门，见第 10 节。
2. **冒烟测试（SMOKE）**：每个新构建必跑的最小集，见第 9.2 节。
3. **功能与适配测试**：第 2~4 节用例表，真机执行。
4. **稳定性与长稳测试**：第 6 节，多轮/长时间运行。
5. **回归测试**：按第 9 节策略，覆盖本次变更影响面。

### 1.2 设备与分辨率矩阵（真机优先，模拟器兜底）

| 档位 | 代表设备/参数 | 分辨率/DPI | Android | 用途 |
|---|---|---|---|---|
| 低配 | 2GB RAM 机型 | 720×1280 / 320dpi | 8.0 (API26) | 低配不崩溃、性能下限 |
| 主测 | 4~8GB RAM 主流机 | 1080×2400 / 420dpi | 12 (API31) | 主功能与适配 |
| 大屏 | 折叠屏/平板 | 2K / 高 DPI | 13 (API33) | 布局拉伸/分屏 |
| 新旧覆盖 | 最小支持版本 | — | 最低 API / 最高 API | 兼容性上下限 |
| 刘海/挖孔 | 全面屏机型 | — | 12+ | 安全区避让 |

> 兼容性覆盖建议至少 4 台真机 + 2 个模拟器 AVD；Brand 覆盖主流国产 ROM（含后台保活策略激进的厂商）各 1 台。

### 1.3 测试数据准备

- 直链：大文件（>500MB）、小文件（<1MB）、含中文/空格文件名的 URL。
- BT：热门种子（多 peer）、冷门种子（可能长时间无速度）、损坏种子。
- 高负载：`100` 条任务的批量导入（用于并发/稳定性用例）。

## 8. 缺陷管理：原生 bug vs 改造引入 bug

### 8.1 判定流程

1. 复现 → 抓 `adb logcat -v time` 与关键堆栈，定位归属层（WebView 壳 / JS 桥 / nodejs-mobile / Fastify server / aria2 / renderer-overrides / 上游 React 逻辑）。
2. 对照上游 `agalwood/Motrix` v2.4.3 在桌面/浏览器 web 模式是否同样存在：
   - 桌面 web 模式**同样存在** → 判为**原生 bug**，记录并视影响排优先级，交付文档需诚实标注。
   - 桌面 web 模式**正常**、仅安卓异常 → 判为**改造引入 bug**，**必须修复**。
3. 归属存疑时，用最小隔离验证（如 renderer-overrides 全关闭后再测）二分定位。

### 8.2 缺陷等级

| 等级 | 定义 | 处理时限（参考） |
|---|---|---|
| Blocker | 崩溃/无法启动/核心下载不可用/合规违规 | 立即，交付前一票否决 |
| Critical | 主功能受损、数据丢失、断点续传失效 | 高优，交付前必修 |
| Major | 明显体验问题、适配错位、性能不达标 | 交付前修或明确降级说明 |
| Minor | 文案/样式/边缘场景 | 可迭代 |

### 8.3 缺陷单必填

编号、标题、等级、归属（原生/改造）、复现步骤、期望/实际、日志与截图、设备与版本、是否已回归。

## 9. 回归策略

### 9.1 分级回归

- **改动影响矩阵**驱动：改 renderer/CSS → 回归 ADPT 全量 + FUNC 冒烟；改 server/engine → 回归 FUNC 下载/BT/限速 + STAB 断网恢复；改壳/桥/前台服务 → 回归 PERM + PERF-004 + DUAL；改构建/依赖 → 全量冒烟 + PERF-001。
- 每个 Blocker/Critical 修复后，回归「对应用例 + 冒烟集」，并在缺陷单记录回归证据（截屏/logcat 片段）。

### 9.2 冒烟集（每次构建必跑，约 30 分钟）

`FUNC-001 / FUNC-002 / FUNC-004 / FUNC-009 / FUNC-010 / FUNC-011 / PERF-001 / PERF-004 / PERM-001 / STAB-001 / STAB-006 / DUAL-001`

### 9.3 回归记录

- 每次回归产出「构建号 → 用例结果矩阵 → 未过项缺陷号」表格，归档到 `reports/`（由 Lead 汇总）。

## 10. 交付物完整性闸门（自动化）

- 脚本：`tests/validate-deliverable.ps1`
- 作用：扫描交付树，校验关键文件是否齐全（BLUEPRINT、docs 7 份、android 关键文件、scripts 4 个、renderer-overrides、third_party/aria2/NOTICE.md、assets 目录），输出 PASS/FAIL 与缺失项。
- 定位：**入场闸门**——文件不齐则不进入功能测试；但「文件存在」不等于「内容合格」，功能/性能/合规仍须按第 2~7 节真机执行。
- 用法见 `tests/README.md`。

## 11. 验收门槛（Exit Criteria）

### 11.1 入场准则（开始正式测试前）

- `tests/validate-deliverable.ps1` 退出码为 0（关键交付物齐全）。
- 可安装的 debug APK 产出，能在主测机安装启动。
- 测试数据与设备矩阵就绪。

### 11.2 出场准则（可交付）

必须**全部**满足：

1. **P0 用例 100% PASS**；**P1 用例 ≥95% PASS** 且未过项均有 Lead 认可的降级说明或排期。
2. **Blocker / Critical 缺陷清零**；**改造引入的 bug 100% 修复并回归通过**；原生 bug 已如实登记并在 `docs/04/05` 标注。
3. **性能达标**：冷启动 ≤3s（主测机）、空闲 PSS ≤200MB、下载中切后台 10min 保活不掉、8h 长稳无泄漏。
4. **合规达标**：最小权限、无后台自启、无强制广告三条 P0 全过。
5. **双模可用**：模式B 默认可用；模式A 可连、失败可降级。
6. 出具有 `tests/validate-deliverable.ps1` 报告 + 功能/性能/稳定性回归矩阵的验收报告（模板见 `tests/README.md`）。

### 11.3 一票否决项

- 应用无法安装/启动，或核心下载链路不可用。
- 存在强制广告、静默自启、超额敏感权限等合规硬伤。
- 断点续传/任务持久化失效导致用户数据丢失。

## 12. 附录：adb / 调试命令速查

```powershell
# 安装/启动/停止
adb install -r app-debug.apk
adb shell am start -W -n <PKG>/<ACT>          # -W 打印 TotalTime（冷启动计时）
adb shell am force-stop <PKG>
adb shell am kill <PKG>                        # 模拟系统回收

# 日志与异常
adb logcat -c; adb logcat -v time | Select-String "<PKG>|FATAL|AndroidRuntime"

# 内存/CPU/服务
adb shell dumpsys meminfo <PKG>
adb shell dumpsys activity services <PKG>
adb shell top -n 1 | Select-String <PKG>

# 权限与包信息
adb shell dumpsys package <PKG> | Select-String "requested permissions|granted=true"
adb shell pm revoke <PKG> android.permission.POST_NOTIFICATIONS

# 网络开关（断网用例）
adb shell svc wifi disable; adb shell svc data disable
adb shell svc wifi enable;  adb shell svc data enable
adb shell dumpsys netstats | Select-String <PKG>

# 主题/旋转/字号
adb shell cmd uimode night yes
adb shell settings put system accelerometer_rotation 0
adb shell settings put system user_rotation 1
adb shell settings put system font_scale 1.3

# 渲染帧耗时（滚动/动画）
adb shell dumpsys gfxinfo <PKG>
```

> 备注：不同 ROM 上 `dumpsys`/`top` 字段略有差异，以实际设备输出为准；网络模拟弱网建议用 Android Emulator 的 Network Delay/Loss 或独立限速路由器。
